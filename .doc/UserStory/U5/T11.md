User story U5: เจ้าหน้าที่ตรวจสอบใบสมัครสหกิจของนักศึกษา แล้วอนุมัติหรือส่งกลับแก้ไข --> จากนั้นอาจารย์พิจารณาอนุมัติ และระบบแจ้งผลให้นักศึกษา

Test case หลักของ U5 (จาก [T4.md](T4.md) ใช้อ้างอิงใน T11–T20)

|---|---|

| TC4 | เจ้าหน้าที่ / อาจารย์ตัดสินพร้อมเหตุผล และนักศึกษาได้รับแจ้งทุกครั้ง |

| TC8 | ตรวจเร็วขึ้น: เหตุผลที่ใช้บ่อย · ช่องที่ต้องแก้ · อนุมัติหลายใบ · ค่าเดิมของฉบับแก้ |
| TC9 | แจ้งเตือนเพิ่ม: แจ้งเจ้าหน้าที่ · เตือนนักศึกษาก่อนหมดเขต |

ขอบเขตและวิธีทดสอบ
-
- ทดสอบ `staff-review.html`, `staff-forms.html`, `notifications.html` + `js/u5.js`
- ใช้ Vitest + jsdom จำลอง backend ด้วย fake `fetch` (ไม่ต้องเปิด server) · เก็บทุก request ไว้ตรวจ method, path, header และ body
- ผู้ใช้จำลอง: `staff01` (STAFF, id 1) · `advisor01` (ADVISOR, id 2) · `6609650001` (STUDENT, id 3)
- โค้ด test: `frontend/tests/u5.test.js` · ผลรันอยู่ใน [T7.md](T7.md)

Unit Test Cases หน้าตรวจคำร้อง (`staff-review.html`)
-
| TC ID | เคส | Input | Expected result |
|---|---|---|---|
| UI-01 | TC3 | เจ้าหน้าที่เปิดหน้า · server มีคำร้อง SUBMITTED 1 ใบ | เรียก `GET /api/applications?status=SUBMITTED` พร้อม header `X-User-Id: 1` · ตารางแสดง 1 แถว มีชื่อ "สมชาย ใจดี" |
| UI-03 | TC3 | ไม่มีคำร้องในสถานะนั้น (server ตอบ `[]`) | แสดงข้อความรายการว่าง (`#emptyMsg`) |
| UI-04 | TC3 | กด "ตรวจ" คำร้องเลขที่ 50 | เปิดหน้ารายละเอียด แสดงคำตอบ 2 ช่อง และเอกสาร `transcript.pdf` |
| UI-06 | TC4 | เปิดหน้ารายละเอียด แล้วยกเลิกการเลือกผลทุกตัวก่อนกดบันทึก | ค่าเริ่มต้นเลือก "อนุมัติ" (ตาม prototype) · ถ้าไม่มีผลที่เลือก แจ้ง `กรุณาเลือกผลการพิจารณา` และไม่เรียก API |
| UI-07 | TC4 | เลือก "ส่งกลับแก้ไข" เหตุผลมีแต่ช่องว่าง | แจ้ง `ยังบันทึกผลไม่ได้ กรุณากรอกเหตุผล` และ `กรุณากรอกเหตุผลเมื่อส่งกลับแก้ไขหรือปฏิเสธ` · ช่องเหตุผลขึ้นกรอบแดง · ไม่เรียก API |
| UI-08 | TC5 | เลือก "อนุมัติ" แล้วกดบันทึก 2 ครั้งติดกัน | ส่ง `POST /api/approvals/50/decision` ครั้งเดียว body `{decision: "APPROVE", comment: null}` |
| UI-09 | TC4 | อนุมัติ · server ตอบ 200 สถานะ `UNDER_REVIEW` | แสดงหน้าบันทึกสำเร็จ ข้อความมีคำว่า "ส่งต่อให้อาจารย์" |
| UI-15 | TC5 | อนุมัติ · server ตอบ 409 `INVALID_STATUS` | อยู่หน้ารายละเอียดเดิม แสดงข้อความจาก server "ไม่ได้อยู่ในขั้นที่คุณพิจารณาได้" |
| UI-13 | TC4 | อาจารย์เปิดหน้า | เรียก `GET /api/applications?status=UNDER_REVIEW` · หัวข้อ "พิจารณาใบสมัคร" · ไม่มีเมนู "แบบฟอร์มคำร้อง" |
| UI-16 | TC5 | นักศึกษาเปิดหน้านี้ | แสดงหน้าไม่มีสิทธิ์ (`#vDenied`) และไม่เรียก API ของเจ้าหน้าที่ (`/api/applications…`) · เมนูนักศึกษาเรียก `/api/requests/me` ได้ เพื่อดูว่าทำถึงขั้นไหน |
| UI-17 | – | backend ไม่ทำงาน (network error) | แสดง `ไม่สามารถเชื่อมต่อระบบได้` |
| UI-18 | TC5 | ยังไม่ login (ไม่มีข้อมูลใน sessionStorage) | ไม่เรียก API ไม่แสดงรายการ (ถูกส่งไป `login.html`) |
| UI-36 | – | login จาก `login.html` แล้วมีแต่ username `staff01` | เรียก `GET /api/users/staff01` ก่อน แล้วใช้ id ที่ได้ใน `X-User-Id` · แสดง "เจ้าหน้าที่ สมศรี ทำงานดี" |
| UI-38 | – | username `nobody` ไม่มีในระบบ (server ตอบ 404) | แสดงข้อความจาก server "ไม่พบบัญชีผู้ใช้ nobody ในระบบ" และปุ่มกลับไปหน้า Login |
