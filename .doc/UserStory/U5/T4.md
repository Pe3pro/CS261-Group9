U5:T4 : Requirement กำหนดรายละเอียด User Story
-
User story U5: เจ้าหน้าที่ตรวจสอบใบสมัครสหกิจของนักศึกษา แล้วอนุมัติหรือส่งกลับแก้ไข --> จากนั้นอาจารย์พิจารณาอนุมัติ และระบบแจ้งผลให้นักศึกษา

User story
-
- **As a** เจ้าหน้าที่ฝ่ายสหกิจศึกษา
- **I want to** สร้าง template แบบฟอร์มคำร้อง และรับใบสมัครที่นักศึกษายื่นเข้ามา เพื่อตรวจ แล้วอนุมัติส่งต่ออาจารย์ ส่งกลับแก้ไข หรือปฏิเสธ
- **So that** ใบสมัครทุกใบถูกตรวจครบตามขั้นตอน อาจารย์พิจารณาต่อได้ทันที และนักศึกษารู้ผลทุกครั้งโดยไม่ต้องมาถามเอง

ผู้ใช้และสิทธิ์
-
| ผู้ใช้ (role) | ทำอะไรได้ | หน้าเว็บ |
|---|---|---|
| เจ้าหน้าที่ (STAFF) | สร้าง / แก้ / เปิดใช้งาน / ดูตัวอย่าง / ปิดรับก่อนกำหนด แบบฟอร์มคำร้อง · ตรวจใบสมัครที่ยื่นเข้ามา (SUBMITTED) ทีละใบหรือหลายใบพร้อมกัน · ดาวน์โหลดรายการเป็น Excel | `staff-forms.html`, `staff-review.html` |
| อาจารย์ (ADVISOR) | พิจารณาใบสมัครที่เจ้าหน้าที่ส่งต่อ (UNDER_REVIEW) เฉพาะนักศึกษาที่ตนเป็นอาจารย์ที่ปรึกษา | `staff-review.html` |
| นักศึกษา (STUDENT) | ดูการแจ้งเตือนผลการพิจารณา (ในระบบและ Email) · แนบไฟล์ตามช่องที่แบบฟอร์มกำหนด (หน้ายื่นคำร้องของ U3) | `notifications.html`, `submit.html` |

ทุกคน login ที่ `login.html` (U1) ก่อน · role มาจาก backend ไม่ต้องเลือกเอง

ขั้นตอนการทำงาน
-
1. เจ้าหน้าที่สร้างแบบฟอร์มคำร้อง (ฉบับร่าง) กำหนดช่องที่ต้องกรอก (รวมช่องแนบไฟล์ได้หลายช่อง) และวันหมดเขต กด "ดูตัวอย่างหน้านักศึกษา" ตรวจหน้าตา แล้วกดเปิดใช้งาน · ถ้าต้องหยุดรับก่อนวันหมดเขต กด "ปิดรับก่อนกำหนด"
2. นักศึกษายื่นคำร้องด้วยแบบฟอร์มที่เปิดใช้งานอยู่ (U3) → ใบสมัครสถานะ `SUBMITTED` · ระบบแจ้งเจ้าหน้าที่ทุกคนว่ามีคำร้องใหม่
3. เจ้าหน้าที่เปิดรายการ "รอตรวจ" เห็นจำนวนคำร้องทุกสถานะบนแท็บ และป้าย "รอนาน" / "ใกล้หมดเขต" ที่ขึ้นก่อน · ดาวน์โหลดรายการเป็น Excel ได้
4. เจ้าหน้าที่ดูข้อมูลนักศึกษา คำตอบทุกช่อง และไฟล์แนบ แล้วเลือกผล (หรือติ๊กหลายใบแล้ว "อนุมัติที่เลือก")
   - อนุมัติ ส่งต่ออาจารย์ → `UNDER_REVIEW` (แจ้งอาจารย์ที่ปรึกษาของนักศึกษาคนนั้นและนักศึกษา)
   - ส่งกลับแก้ไข → `NEED_CORRECTION` (ต้องมีเหตุผล เลือกจากเหตุผลที่ใช้บ่อยได้ และติ๊กช่องที่ต้องแก้ได้ · ระบบเก็บคำตอบ ณ ตอนนั้นไว้เทียบ · แจ้งนักศึกษา)
   - ปฏิเสธ → `REJECTED` (ต้องมีเหตุผล แจ้งนักศึกษา)
5. อาจารย์เปิดรายการ "รอพิจารณา" (เฉพาะนักศึกษาของตน) แล้วเลือกผล: อนุมัติ → `APPROVED` · ส่งกลับแก้ไข · ปฏิเสธ (แจ้งนักศึกษาทุกครั้ง)
6. นักศึกษาเห็นผลในหน้า "การแจ้งเตือน" และใน Email พร้อมเหตุผลและช่องที่ต้องแก้ (ถ้ามี) · ถ้าถูกส่งกลับแต่ยังไม่ส่งใหม่ ระบบเตือนทุกเช้าเมื่อเหลือไม่เกิน 2 วันก่อนหมดเขต
7. นักศึกษาแก้แล้วส่งใหม่ → `SUBMITTED` อีกครั้ง · ระบบแจ้งเจ้าหน้าที่ว่าเป็นฉบับแก้ · หน้าตรวจแสดงค่าเดิมของช่องที่เปลี่ยน

กฎของระบบ
-
| หัวข้อ | กฎ |
|---|---|
| แบบฟอร์ม | ต้องมีชื่อ และอย่างน้อย 1 ช่อง · ชื่อช่องห้ามซ้ำ · ช่องชนิด "ตัวเลือก" ต้องมีตัวเลือกอย่างน้อย 1 รายการ |
| เปิดใช้งาน | ต้องกำหนดวันหมดเขตที่ยังไม่ผ่านไป · เปิดใช้งานได้ทีละ 1 ฉบับ ฉบับเดิมเปลี่ยนเป็น "เลิกใช้" อัตโนมัติ |
| แก้ไขแบบฟอร์ม | แก้ได้เฉพาะฉบับร่าง · ฉบับที่เปิดใช้งานแล้วต้อง "สร้างฉบับใหม่จากฉบับนี้" |
| การพิจารณา | เจ้าหน้าที่ตัดสินได้เฉพาะ `SUBMITTED` · อาจารย์ตัดสินได้เฉพาะ `UNDER_REVIEW` |
| เหตุผล | ส่งกลับแก้ไขหรือปฏิเสธต้องกรอกเหตุผลทุกครั้ง |
| ตัดสินซ้ำ | ใบสมัครที่ตัดสินไปแล้ว หรือมีคนตัดสินพร้อมกัน ได้ 409 และไม่บันทึกซ้ำ |
| การแจ้งเตือน | ทุกการตัดสินต้องแจ้งนักศึกษา (ในระบบและ Email · Email ส่งหลังบันทึกผลสำเร็จ ถ้าส่งไม่ได้ผลการพิจารณายังอยู่ครบ) · อนุมัติของเจ้าหน้าที่ต้องแจ้งอาจารย์ที่ปรึกษาของนักศึกษาคนนั้นด้วย · ผู้ใช้อ่านได้เฉพาะแจ้งเตือนของตัวเอง |
| สิทธิ์อาจารย์ | อาจารย์เห็นและตัดสินได้เฉพาะคำร้องของนักศึกษาที่ตนเป็นอาจารย์ที่ปรึกษา (`students.advisor_id`) · คำร้องอื่นได้ 403 |
| ช่องแนบไฟล์ | แบบฟอร์มมีช่องชนิด "แนบไฟล์" ได้หลายช่อง (PDF ไม่เกิน 10 MB) · ช่องไฟล์ช่องแรกคือ Transcript เดิม · ช่องไฟล์ที่บังคับต้องมีไฟล์ก่อนส่ง |
| ปิดรับก่อนกำหนด | ทำได้เฉพาะฉบับที่เปิดใช้งานและยังไม่หมดเขต · วันหมดเขตเลื่อนมาเป็นเวลาที่กด · คำร้องที่ส่งแล้วยังพิจารณาต่อได้ |
| ป้ายเตือนในรายการ | "ใกล้หมดเขต" = แบบฟอร์มหมดเขตภายใน 2 วัน · "รอนาน" = รอตรวจตั้งแต่ 3 วัน · ใช้กับ `SUBMITTED` / `UNDER_REVIEW` · คำร้องที่มีป้ายขึ้นก่อน |
| ช่องที่ต้องแก้ | ตอนส่งกลับแก้ไข เลือกได้เฉพาะช่องในแบบฟอร์มของคำร้องนั้น · ระบบต่อท้ายเหตุผลว่า "ช่องที่ต้องแก้: …" |
| อนุมัติหลายใบ | ไม่เกิน 100 ใบต่อครั้ง · ใบที่อนุมัติไม่ได้ (สถานะเปลี่ยน / ไม่มีสิทธิ์) ถูกข้ามพร้อมเหตุผล ใบอื่นยังสำเร็จ |
| Excel | ไฟล์ CSV (UTF-8 เปิดใน Excel ภาษาไทยไม่เพี้ยน) · อาจารย์ได้เฉพาะนักศึกษาของตน |
| แจ้งเจ้าหน้าที่ | ทุกครั้งที่มีคำร้องใหม่หรือฉบับแก้ส่งเข้ามา แจ้งเจ้าหน้าที่ทุกคนที่ใช้งานอยู่ (ในระบบ) |
| เตือนก่อนหมดเขต | ทุกวัน 08:00 (เวลาไทย) เตือนนักศึกษาที่คำร้อง `NEED_CORRECTION` และแบบฟอร์มหมดเขตภายใน 2 วัน · เตือนไม่เกินวันละครั้งต่อคำร้อง |

Acceptance criteria (test case หลักของ U5)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 | เจ้าหน้าที่สร้างแบบฟอร์มและเปิดใช้งานได้ นักศึกษาใช้ฉบับที่เปิดอยู่ยื่นคำร้อง |
| TC2 | แบบฟอร์มข้อมูลไม่ครบหรือผิด (ไม่มีชื่อ ไม่มีช่อง ชื่อช่องซ้ำ ไม่มีวันหมดเขต) ถูกปฏิเสธ |
| TC3 | เจ้าหน้าที่เห็นคำร้องที่ยื่นเข้ามาครบ: ข้อมูลนักศึกษา คำตอบทุกช่อง และไฟล์ PDF |
| TC4 | เจ้าหน้าที่อนุมัติส่งต่ออาจารย์ หรือส่งกลับแก้ไข/ปฏิเสธพร้อมเหตุผล และนักศึกษาได้รับแจ้งทุกครั้ง |
| TC5 | การตัดสินที่ไม่ถูกต้องถูกปฏิเสธ: ตัดสินซ้ำ ข้ามขั้น หรือผู้ใช้ที่ไม่มีสิทธิ์ (รวมอาจารย์ที่ไม่ใช่อาจารย์ที่ปรึกษา) |
| TC6 | แบบฟอร์ม: มีช่องแนบไฟล์หลายช่องและนักศึกษาต้องแนบครบ · ดูตัวอย่างหน้านักศึกษาได้ก่อนบันทึก · ปิดรับก่อนกำหนดแล้วนักศึกษายื่นไม่ได้ |
| TC7 | ภาพรวมคำร้อง: เห็นจำนวนทุกสถานะ · คำร้องรอนาน / ใกล้หมดเขตมีป้ายและขึ้นก่อน · ดาวน์โหลดรายการเป็น Excel ได้ |
| TC8 | ตรวจเร็วขึ้น: เลือกเหตุผลที่ใช้บ่อย · ระบุช่องที่ต้องแก้ · อนุมัติหลายใบพร้อมกัน · เห็นค่าเดิมของช่องที่นักศึกษาแก้ |
| TC9 | แจ้งเตือนเพิ่ม: เจ้าหน้าที่ได้รับแจ้งเมื่อมีคำร้องใหม่ / ฉบับแก้ · นักศึกษาได้รับเตือนก่อนหมดเขตถ้ายังไม่ส่งฉบับแก้ |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role` (หน้า U5 ส่ง `X-User-Id` ไปกับทุก request)
- U3 ยื่นคำร้อง: สร้างใบสมัคร `SUBMITTED` ในตาราง `applications` · ระหว่างที่ U3 ยังไม่เสร็จ ใช้ใบสมัครตัวอย่างจาก `DemoDataSeeder`
- U3 ใช้ร่วมกัน: หน้ายื่นคำร้องแสดงช่องแนบไฟล์เพิ่มตามแบบฟอร์ม (`POST /api/requests/{id}/documents?fieldId=`) · ตอนส่งระบบแจ้งเจ้าหน้าที่ · เหตุผลที่ส่งกลับ (รวมช่องที่ต้องแก้) แสดงในหน้ายื่นคำร้อง

ไม่อยู่ในขอบเขตของ U5
-
- การยื่นและแก้ไขคำร้องของนักศึกษา (U3) · การจับคู่บริษัท (U4)
- ไฟล์ Excel ชนิด .xlsx (ระบบให้ไฟล์ CSV ที่เปิดใน Excel ได้) · แจ้งเจ้าหน้าที่ทาง Email (แจ้งในระบบเท่านั้น)
