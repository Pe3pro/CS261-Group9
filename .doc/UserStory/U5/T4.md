U5:T4 : Requirement กำหนดรายละเอียด User Story
-
User story U5: เจ้าหน้าที่ตรวจสอบใบสมัครสหกิจของนักศึกษา แล้วอนุมัติหรือส่งกลับแก้ไข --> จากนั้นอาจารย์พิจารณาอนุมัติ และระบบแจ้งผลให้นักศึกษา

User story
-
- **As a** เจ้าหน้าที่ฝ่ายสหกิจศึกษา
- **I want to** สร้าง template แบบฟอร์มคำร้อง และรับใบสมัครที่นักศึกษายื่นเข้ามา เพื่อตรวจ แล้วอนุมัติส่งต่ออาจารย์ ส่งกลับแก้ไข หรือปฏิเสธ
- **So that** ใบสมัครทุกใบถูกตรวจครบตามขั้นตอน อาจารย์พิจารณาต่อได้ทันที และนักศึกษารู้ผลทุกครั้งโดยไม่ต้องมาถามเอง

ผู้ใช้และสิทธิ์
-
| ผู้ใช้ (role) | ทำอะไรได้ | หน้าเว็บ |
|---|---|---|
| เจ้าหน้าที่ (STAFF) | สร้าง / แก้ / เปิดใช้งานแบบฟอร์มคำร้อง · ตรวจใบสมัครที่ยื่นเข้ามา (SUBMITTED) | `staff-forms.html`, `staff-review.html` |
| อาจารย์ (ADVISOR) | พิจารณาใบสมัครที่เจ้าหน้าที่ส่งต่อ (UNDER_REVIEW) | `staff-review.html` |
| นักศึกษา (STUDENT) | ดูการแจ้งเตือนผลการพิจารณา | `notifications.html` |

ทุกคน login ที่ `login.html` (U1) ก่อน · role มาจาก backend ไม่ต้องเลือกเอง

ขั้นตอนการทำงาน
-
1. เจ้าหน้าที่สร้างแบบฟอร์มคำร้อง (ฉบับร่าง) กำหนดช่องที่ต้องกรอก และวันหมดเขต แล้วกดเปิดใช้งาน
2. นักศึกษายื่นคำร้องด้วยแบบฟอร์มที่เปิดใช้งานอยู่ (U3) → ใบสมัครสถานะ `SUBMITTED`
3. เจ้าหน้าที่เปิดรายการ "รอตรวจ" ดูข้อมูลนักศึกษา คำตอบทุกช่อง และไฟล์แนบ แล้วเลือกผล
   - อนุมัติ ส่งต่ออาจารย์ → `UNDER_REVIEW` (แจ้งอาจารย์และนักศึกษา)
   - ส่งกลับแก้ไข → `NEED_CORRECTION` (ต้องมีเหตุผล แจ้งนักศึกษา)
   - ปฏิเสธ → `REJECTED` (ต้องมีเหตุผล แจ้งนักศึกษา)
4. อาจารย์เปิดรายการ "รอพิจารณา" แล้วเลือกผล: อนุมัติ → `APPROVED` · ส่งกลับแก้ไข · ปฏิเสธ (แจ้งนักศึกษาทุกครั้ง)
5. นักศึกษาเห็นผลในหน้า "การแจ้งเตือน" พร้อมเหตุผล (ถ้ามี)

กฎของระบบ
-
| หัวข้อ | กฎ |
|---|---|
| แบบฟอร์ม | ต้องมีชื่อ และอย่างน้อย 1 ช่อง · ชื่อช่องห้ามซ้ำ · ช่องชนิด "ตัวเลือก" ต้องมีตัวเลือกอย่างน้อย 1 รายการ |
| เปิดใช้งาน | ต้องกำหนดวันหมดเขตที่ยังไม่ผ่านไป · เปิดใช้งานได้ทีละ 1 ฉบับ ฉบับเดิมเปลี่ยนเป็น "เลิกใช้" อัตโนมัติ |
| แก้ไขแบบฟอร์ม | แก้ได้เฉพาะฉบับร่าง · ฉบับที่เปิดใช้งานแล้วต้อง "สร้างฉบับใหม่จากฉบับนี้" |
| การพิจารณา | เจ้าหน้าที่ตัดสินได้เฉพาะ `SUBMITTED` · อาจารย์ตัดสินได้เฉพาะ `UNDER_REVIEW` |
| เหตุผล | ส่งกลับแก้ไขหรือปฏิเสธต้องกรอกเหตุผลทุกครั้ง |
| ตัดสินซ้ำ | ใบสมัครที่ตัดสินไปแล้ว หรือมีคนตัดสินพร้อมกัน ได้ 409 และไม่บันทึกซ้ำ |
| การแจ้งเตือน | ทุกการตัดสินต้องแจ้งนักศึกษา · อนุมัติของเจ้าหน้าที่ต้องแจ้งอาจารย์ด้วย · ผู้ใช้อ่านได้เฉพาะแจ้งเตือนของตัวเอง |

Acceptance criteria (test case หลักของ U5)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 | เจ้าหน้าที่สร้างแบบฟอร์มและเปิดใช้งานได้ นักศึกษาใช้ฉบับที่เปิดอยู่ยื่นคำร้อง |
| TC2 | แบบฟอร์มข้อมูลไม่ครบหรือผิด (ไม่มีชื่อ ไม่มีช่อง ชื่อช่องซ้ำ ไม่มีวันหมดเขต) ถูกปฏิเสธ |
| TC3 | เจ้าหน้าที่เห็นคำร้องที่ยื่นเข้ามาครบ: ข้อมูลนักศึกษา คำตอบทุกช่อง และไฟล์ PDF |
| TC4 | เจ้าหน้าที่อนุมัติส่งต่ออาจารย์ หรือส่งกลับแก้ไข/ปฏิเสธพร้อมเหตุผล และนักศึกษาได้รับแจ้งทุกครั้ง |
| TC5 | การตัดสินที่ไม่ถูกต้องถูกปฏิเสธ: ตัดสินซ้ำ ข้ามขั้น หรือผู้ใช้ที่ไม่มีสิทธิ์ |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role` (หน้า U5 ส่ง `X-User-Id` ไปกับทุก request)
- U3 ยื่นคำร้อง: สร้างใบสมัคร `SUBMITTED` ในตาราง `applications` · ระหว่างที่ U3 ยังไม่เสร็จ ใช้ใบสมัครตัวอย่างจาก `DemoDataSeeder`

ไม่อยู่ในขอบเขตของ U5
-
- การยื่นและแก้ไขคำร้องของนักศึกษา (U3) · การจับคู่บริษัท (U4) · ส่งอีเมลแจ้งเตือน (แจ้งในระบบเท่านั้น)
