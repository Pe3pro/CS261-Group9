ไฟล์ที่พัฒนา (`demo/src/main/java/com/example/demo/`)
-
| ไฟล์ | หน้าที่ |
|---|---|
| `controller/AuthController.java` | `POST /api/auth/login` |
| `service/AuthService.java` | ตรวจ input → ตรวจกับ TU REST API → บันทึก/อัปเดตผู้ใช้ → สร้าง token (อายุ 8 ชั่วโมง) |
| `service/TuApiClient.java` | เรียก `https://restapi.tu.ac.th/api/v1/auth/Ad/verify` พร้อม header `Application-Key` (timeout 5/10 วินาที) |
| `dto/LoginRequest.java` | `username`, `password` (`toString` ไม่แสดงรหัสผ่าน) |
| `dto/LoginResponse.java` | `accessToken`, `tokenType`, `expiresAt`, `userId`, `username`, `fullName`, `role` |
| `dto/TuVerifyResponse.java` | ผลจาก TU REST API (ใช้ภายใน Backend) |
| `application.properties` | `tu.api.base-url`, `tu.api.key=${TU_API_KEY:}`, บัญชีทดลอง |

- error ทั้งหมดใช้ `ApiException` → `ApiExceptionHandler` → `ErrorResponse(code, message)` ตัวเดียวกับ User Story อื่น
- **Application-Key อ่านจาก environment variable `TU_API_KEY` เท่านั้น** (ไฟล์ `.env` ข้าง `docker-compose.yml` ซึ่งอยู่ใน `.gitignore`)
- บัญชีทดลองของ `DemoDataSeeder` (`staff01`, `advisor01`, `6609650001`, `6609650002`) ไม่มีในระบบ มธ. จึง login ด้วยรหัสผ่านทดลอง `1234` ได้โดยไม่เรียก TU REST API · ปิดได้ด้วย `APP_AUTH_DEMO_PASSWORD=` (ค่าว่าง)

ทดสอบ API ด้วย Postman
-
Collection: [`.doc/postman/U1-Login.postman_collection.json`](../../postman/U1-Login.postman_collection.json) (ไม่มี key / รหัสผ่านในไฟล์)

วิธีรัน
1. `.env` ข้าง `docker-compose.yml` มี `TU_API_KEY=...` (ไฟล์นี้อยู่ใน `.gitignore`) แล้ว `docker compose up -d --build`
2. Postman → Import Collection แล้วสร้าง Environment ที่มี `tu_username`, `tu_password` (type secret) · **ห้าม export Environment**
3. Run collection (PM-L05 ส่งรหัสผิดไปที่ระบบ มธ. จริง ให้รันครั้งเดียว)
