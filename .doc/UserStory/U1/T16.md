U1:T16 ออกแบบ User Acceptance Test ตาม User Story
-
User story U1
-
- **As a** นักศึกษาและเจ้าหน้าที่ มธ.
- **I want to** เข้าสู่ระบบด้วย Username และ Password ของสำนักทะเบียน (บัญชี มธ.)
- **So that** เข้าใช้งานแอปพลิเคชันได้โดยไม่ต้องสมัครบัญชีใหม่ และเห็นเฉพาะเมนูของบทบาทตัวเอง

ผู้ทดสอบ: นักศึกษาจริง 3–5 คน (บัญชี มธ. ของตัวเอง) + ผู้รับบทเจ้าหน้าที่ / อาจารย์ 1 คน (บัญชีทดลอง) · ทีมไม่บอกขั้นตอน และ**ไม่ดู ไม่จด ไม่ถามรหัสผ่าน**ของผู้ทดสอบ

Test cases
-
| TC ID | เคส | Given | When | Then | เกณฑ์ที่ user ยอมรับได้ |
|---|---|---|---|---|---|
| UAT-L01 | TC1 | นักศึกษามีบัญชี มธ. | กรอกรหัสนักศึกษา + รหัสผ่าน แล้วกดเข้าสู่ระบบ | เข้าหน้าตรวจสอบคุณสมบัติ | ทำเองได้ภายใน 1 นาที ไม่ต้องสมัครบัญชีใหม่ |
| UAT-L02 | TC2 | เจ้าหน้าที่ / อาจารย์ | login | เห็นเฉพาะเมนูของบทบาทตัวเอง | ไม่เห็นหน้าของนักศึกษา ไม่ต้องเลือกบทบาทเอง |
| UAT-L03 | TC3 | ผู้ใช้พิมพ์รหัสผ่านผิด | กดเข้าสู่ระบบ | แจ้งว่า Username หรือ Password ไม่ถูกต้อง | เข้าใจทันทีว่าต้องกรอกใหม่ ไม่ต้องพิมพ์ Username ซ้ำ |
| UAT-L04 | TC4 | ลืมกรอกช่องใดช่องหนึ่ง | กดเข้าสู่ระบบ | แจ้งให้กรอกให้ครบ | ข้อความอ่านเข้าใจ ไม่มี error ทางเทคนิค |
| UAT-L05 | TC5 | ระบบของ มธ. ใช้งานไม่ได้ | กดเข้าสู่ระบบ | แจ้งว่าเชื่อมต่อระบบของมหาวิทยาลัยไม่ได้ | รู้ว่าไม่ใช่ความผิดของตัวเอง และให้ลองใหม่ภายหลัง |
| UAT-L06 | – | login อยู่ | กดออกจากระบบ | กลับหน้า login | เครื่องสาธารณะใช้ต่อได้อย่างปลอดภัย |

เกณฑ์ผ่าน UAT โดยรวม
-
- UAT-L01 ถึง UAT-L05 ต้องผ่านทุกข้อ (เคสบังคับตาม user story)
- ผู้ทดสอบอย่างน้อย 80% ทำ UAT-L01 สำเร็จเองโดยไม่ต้องถามทีม
- ไม่มีปัญหาที่ทำให้ login ไม่ได้ค้างอยู่ · บันทึกผลอยู่ใน T20.md
