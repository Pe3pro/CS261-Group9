U1:T6 Design Interaction ระหว่าง API_DAO_DB
-
User story U1: นักศึกษาและเจ้าหน้าที่เข้าสู่ระบบด้วย Username และ Password ของสำนักทะเบียน (บัญชี มธ.) เพื่อเข้าใช้งานแอปพลิเคชัน

ระบบไม่เก็บรหัสผ่านเอง แต่ส่งไปตรวจสอบกับ TU REST API ของมหาวิทยาลัย ถ้าผ่าน จึงบันทึกหรืออัปเดตข้อมูลผู้ใช้ลงตาราง `users` (และ `students` ถ้าเป็นนักศึกษา) แล้วส่ง Token, `userId` และ Role กลับไปที่หน้าเว็บ

U1 **ใช้ Entity / Repository ที่มีอยู่แล้วใน Develop** (`User`, `Role`, `Student`, `UserRepository`, `StudentRepository`) และใช้ `ApiException` / `ErrorResponse` ร่วมกับ User Story อื่น ไม่สร้างตารางใหม่

Sequence Diagram
-
![.doc/UserStory/U1/U1-T6 Sequence Diagram.png](<U1-T6 Sequence Diagram.png>)

- **กรณีสำเร็จ** (`status = true`): `findByUsername` ค้นหาผู้ใช้
  - **มีอยู่แล้ว**: ใช้ `role` เดิม ถ้า `active = false` ตอบ `403 FORBIDDEN` ไม่เช่นนั้นอัปเดต `fullName` / `email` แล้ว `save`
  - **ยังไม่มี**: แปลง `type` เป็น Role (`student` → `STUDENT`, `employee` → `STAFF`) แล้ว `save` User ใหม่ ถ้าเป็นนักศึกษาให้ `save` Student (`studentId` = username, `faculty`, `major` = department) ด้วย
  - ตอบ `200 OK` พร้อม `LoginResponse`
- **กรณีไม่สำเร็จ** (`status = false`): โยน `ApiException.unauthorized("INVALID_CREDENTIALS", ...)` → `ApiExceptionHandler` ตอบ `401` พร้อม `ErrorResponse`
- กรอกข้อมูลไม่ครบ ตอบ `400 VALIDATION_ERROR` · เชื่อมต่อ TU REST API ไม่ได้ ตอบ `502 TU_API_UNAVAILABLE`

DAO class diagram
-
![.doc/UserStory/U1/U1-T6 DAO Class Diagram.png](<U1-T6 DAO Class Diagram.png>)

| Repository | Method | หน้าที่ใน U1 |
|---|---|---|
| `UserRepository` | `findByUsername(username)` | ค้นหาผู้ใช้จากรหัสนักศึกษา / รหัสบุคลากร |
| `UserRepository` | `save(user)` | บันทึกผู้ใช้ใหม่ หรืออัปเดต `fullName` / `email` ของผู้ใช้เดิม |
| `StudentRepository` | `findByUserId(userId)` | ตรวจว่ามีข้อมูลนักศึกษาของผู้ใช้นี้แล้วหรือยัง |
| `StudentRepository` | `save(student)` | บันทึกข้อมูลนักศึกษาครั้งแรกที่ Log in |

ER diagram
-
![.doc/UserStory/U1/U1-T6 ER diagram.png](<U1-T6 ER diagram.png>)

- `users.username` เป็น Unique Key ใช้ค้นหาผู้ใช้ตอน Log in
- `users.role` เก็บเป็นข้อความ `STUDENT` / `STAFF` / `ADVISOR` / `ADMIN`
- `users.password_hash` มีอยู่ในตารางเดิม แต่ **U1 ไม่ใช้** เพราะตรวจสอบรหัสผ่านกับระบบของมหาวิทยาลัยทุกครั้ง
- `students.user_id` อ้างอิง `users.id` (1 ต่อ 0..1) · ตารางของ User Story อื่น (เช่น คำร้องใน U3) อ้างอิงผู้ใช้ผ่าน `users.id`
