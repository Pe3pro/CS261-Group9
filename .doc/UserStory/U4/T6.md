U4:T6 : ออกแบบ Interaction ระหว่าง API–DAO–DB (ระบบจับคู่บริษัท (จัดอันดับ))
-
ออกแบบลำดับการทำงานและการเชื่อมต่อระหว่าง API, DAO (Data Access Object) และฐานข้อมูลของระบบจับคู่บริษัท (จัดอันดับ) เพื่อให้ดึง/บันทึกข้อมูลได้ถูกต้อง
-

ส่วนประกอบของระบบ
-
Controller → Service / Business Logic → DAO / Repository → Entity / ORM → Database

| ส่วนประกอบ | หน้าที่ |
|---|---|
| UI (`ranking.html`) | แสดงช่องอันดับ 1–5 ให้นักศึกษาค้นหาบริษัทที่เปิดรับ จัดอันดับ และยืนยัน |
| `RankingController` | `GET /api/companies`, `GET /api/students/me/company-ranking`, `PUT /api/students/me/company-ranking` |
| `CompanyService` | ดึงบริษัทที่เปิดรับ |
| `RankingService` | ตรวจสิทธิ์และอันดับ (ผ่าน U2, ยังไม่ยื่นคำร้อง, ครบ 5, ไม่ซ้ำ, บริษัทยังเปิดรับ) แล้วบันทึก |
| `CompanyRepository` | ดึงบริษัทตามสถานะ |
| `CompanyRankingRepository` | บันทึก / ดึง / ลบอันดับบริษัทของนักศึกษา |
| MySQL | ตาราง `companies`, `company_rankings` |

วาด Sequence Diagram
-
```mermaid
sequenceDiagram
    actor Student as นักศึกษา
    participant UI as ranking.html
    participant API as RankingController
    participant SVC as CompanyService / RankingService
    participant DAO as Repository
    participant DB as MySQL

    Student->>UI: เปิดหน้าจับคู่บริษัท
    UI->>API: GET /api/companies
    API->>SVC: getOpenCompanies()
    SVC->>DAO: CompanyRepository.findByStatus(OPEN)
    DAO->>DB: SELECT * FROM companies WHERE status = 'OPEN'
    DB-->>UI: 200 OK Company List
    UI->>API: GET /api/students/me/company-ranking
    API->>SVC: getMyRanking()
    SVC->>DAO: CompanyRankingRepository.findByStudentIdOrderByRankNoAsc(studentId)
    DAO->>DB: SELECT * FROM company_rankings WHERE student_id = ? ORDER BY rank_no
    DB-->>UI: 200 OK อันดับที่เคยบันทึก (ยังไม่เคย = รายการว่าง)

    Student->>UI: ค้นหาและเลือกบริษัทลงอันดับ 1–5
    UI->>UI: ซ่อนบริษัทที่เลือกในอันดับอื่นแล้ว · นับ "เลือกแล้ว X จาก 5"

    Student->>UI: กด "ยืนยันการเลือก"
    alt เลือกไม่ครบ 5 อันดับ
        UI-->>Student: "กรุณาเลือกบริษัทให้ครบ 5 อันดับ" (ไม่เรียก API)
    else เลือกครบ 5 อันดับ
        UI->>API: PUT /api/students/me/company-ranking {companyIds: [5 ตัว]}
        API->>SVC: saveMyRanking()
        SVC->>SVC: ตรวจ ยังไม่ยื่นคำร้อง · ผ่าน U2 · ครบ 5 · ไม่ซ้ำ · บริษัทเปิดรับ
        alt อันดับถูกต้อง
            SVC->>DAO: CompanyRankingRepository.deleteByStudentId · saveAll
            DAO->>DB: DELETE / INSERT INTO company_rankings
            API-->>UI: 200 OK อันดับ 1–5
            UI-->>Student: "สำเร็จ บันทึกลำดับเรียบร้อยแล้ว"
        else ผิดเงื่อนไข
            API-->>UI: 400 / 403 / 409 พร้อม message
            UI-->>Student: แสดงข้อความจาก server (ยังไม่บันทึก)
        end
    end
```

- **ดูบริษัท**: ได้เฉพาะบริษัท `OPEN` · ไม่มีบริษัทเปิดรับได้ list ว่าง
- **ดูอันดับ**: เรียงตาม `rank_no` 1 → 5 · ยังไม่เคยบันทึกได้ list ว่าง
- **บันทึกอันดับ**: ลบชุดเดิมของนักศึกษาแล้วบันทึกชุดใหม่ 5 แถว · ผิดเงื่อนไขต้องไม่บันทึก

| Error | เมื่อไร |
|---|---|
| 400 `INVALID_RANKING` / `DUPLICATE_COMPANY` / `COMPANY_NOT_FOUND` / `COMPANY_CLOSED` | ไม่ครบ 5 · ซ้ำ · ไม่มีบริษัทนี้ · บริษัทปิดรับแล้ว |
| 403 `NOT_ELIGIBLE` | ยังไม่ผ่านการตรวจคุณสมบัติ (U2) |
| 409 `RANKING_LOCKED` | ยื่นคำร้อง (U3) แล้ว |
