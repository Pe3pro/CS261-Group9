U4:T6 Design Interaction ระหว่าง API_DAO_DB
-
User story U4: Design-> ออกแบบ Interaction ระหว่าง API–DAO–DB (ระบบจับคู่บริษัท (จัดอันดับ))

ออกแบบลำดับการทำงานและการเชื่อมต่อระหว่าง API, DAO (Data Access Object) และฐานข้อมูลของระบบจับคู่บริษัท (จัดอันดับ) เพื่อให้ดึง/บันทึกข้อมูลได้ถูกต้อง

Sequence Diagram
-
![Sequence Diagram](<U4-10 Sequence diagram.png>)

| ลำดับ | ขั้นตอน | Request | API → Service → Database |
|---|---|---|---|
| 1 | นักศึกษาดูบริษัทที่เปิดรับ | GET /api/companies | ค้นหาบริษัท → ดึงบริษัทที่เปิดรับ → Company List |
| 2 | เลือกบริษัทและดูตำแหน่ง | GET /api/companies/{id}/positions | ค้นหาตำแหน่ง → ดึงตำแหน่งที่เปิดรับ → Position List |
| 3 | กรอกใบสมัคร | POST /api/applications | สร้างใบสมัคร → บันทึกใบสมัคร → Application ID |
| 4 | เลือกบริษัท 5 อันดับ | PUT /api/applications/{id}/choices | ตรวจสอบและบันทึกตัวเลือก → บันทึกอันดับ 1–5 → Success |

DAO class diagram
-
![DAO Class Diagram](<U4-T6 DAO Class Diagram.png>)

| ชั้น | หน้าที่ |
|---|---|
| Controller | รับ HTTP Request จาก Frontend |
| Service / Business Logic | ตรวจสิทธิ์ ตรวจข้อมูล และจัดการขั้นตอนอนุมัติ |
| DAO / Repository | ค้นหา เพิ่ม แก้ไข และลบข้อมูล |
| Entity / ORM | แมปคลาส Java กับตารางฐานข้อมูล |
| Database | PostgreSQL Database |

| Repository | Method |
|---|---|
| CompanyRepository | findByStatus(), findByNameContainingIgnoreCase() |
| CompanyPositionRepository | findByCompanyId(), findOpenPositions() |
| ApplicationRepository | findByStudentId(), findByStatus(), findById() |
| ApplicationChoiceRepository | findByApplicationIdOrderByRankAsc() |
