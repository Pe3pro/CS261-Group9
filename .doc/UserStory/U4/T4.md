U4:T4 : กำหนดรายละเอียด User Story (ระบบจับคู่บริษัท (จัดอันดับ))
-
วิเคราะห์ requirement และ pain point ของระบบจับคู่บริษัท (จัดอันดับ) แจกแจง stakeholder แต่ละฝ่าย และร่าง use case ของแต่ละกรณี เพื่อใช้เป็นฐานในการออกแบบและทดสอบ
-

หา user story ตาม requirement และ pain point
-
**User story**

- **As a** นศ.มธ. ที่มีสิทธิ์ไปฝึกสหกิจศึกษา
- **I want to** เลือกบริษัทที่ตนสนใจ หรือจับคู่บริษัทที่ต้องการไปฝึกสหกิจศึกษา จากตัวเลือกที่ทางคณะ / สาขามีและสามารถไปได้
- **So that** นักศึกษาได้บริษัทที่ตนเองสนใจ หรือบริษัทอื่น ๆ ที่อยู่ใน List ได้อย่างถูกต้อง

**Pain point ของระบบเดิม**

| ผู้ได้รับผลกระทบ | ปัญหา |
|---|---|
| นักศึกษา | ไม่รู้ว่าบริษัทไหนยังเปิดรับ |
| นักศึกษา | ต้องกรอกรายชื่อบริษัทที่เลือกลงกระดาษ เขียนชื่อผิดหรือเลือกซ้ำได้ |
| เจ้าหน้าที่ | ต้องรวบรวมอันดับที่นักศึกษาเลือกจากกระดาษเอง และตรวจเองว่าบริษัทยังเปิดรับไหม |

แจกแจง stakeholder ของแต่ละฝ่าย
-
| Stakeholder | ความต้องการต่อ U4 | หน้าเว็บ |
|---|---|---|
| นักศึกษา (STUDENT) | เห็นเฉพาะบริษัทที่เปิดรับ ค้นหาและจัดอันดับ 5 อันดับได้เอง เห็นอันดับที่บันทึกไว้ | `ranking.html` |
| เจ้าหน้าที่ฝ่ายสหกิจ (STAFF) | ได้อันดับบริษัทของนักศึกษาที่ถูกต้อง ไม่มีบริษัทซ้ำหรือบริษัทที่ปิดรับแล้ว · เปิด–ปิดรับบริษัทได้ | – |
| U6 ระบบจับคู่ (Matching) | ใช้อันดับที่บันทึกไว้ไปจับคู่กับโควตาของบริษัท | – |

นักศึกษาต้อง login (U1) และผ่านการตรวจสอบคุณสมบัติ (U2) ก่อน

ร่าง use case ของแต่ละกรณี
-
**ขั้นตอนการทำงาน**

1. นักศึกษาที่ผ่านเกณฑ์เปิดหน้าจับคู่บริษัท ระบบดึงรายชื่อบริษัทที่เปิดรับ (`GET /api/companies`) และอันดับที่เคยบันทึกไว้ (`GET /api/students/me/company-ranking`)
2. นักศึกษาคลิกช่องอันดับ 1–5 แล้วพิมพ์ค้นหาบริษัทจากชื่อ บริษัทที่เลือกในอันดับอื่นแล้วจะไม่แสดงซ้ำ
3. กด "ล้าง" ที่อันดับใดอันดับหนึ่ง หรือ "ล้างทั้งหมด" เพื่อเลือกใหม่ ระหว่างเลือกเห็น "เลือกแล้ว X จาก 5 อันดับ"
4. เลือกครบ 5 อันดับแล้วกด "ยืนยันการเลือก"
5. ระบบตรวจอันดับ แล้วบันทึก (`PUT /api/students/me/company-ranking`) แสดง "สำเร็จ บันทึกลำดับเรียบร้อยแล้ว"
6. กลับมาเปิดหน้าอีกครั้ง อันดับที่บันทึกไว้ยังอยู่

**Use case**

| UC | ชื่อ | ผู้ใช้ | เงื่อนไขก่อน | ผลลัพธ์ |
|---|---|---|---|---|
| UC-01 | ดูบริษัทที่เปิดรับ | นักศึกษา | login และผ่าน U2 | เห็นเฉพาะบริษัทสถานะ `OPEN` |
| UC-02 | ค้นหาและเลือกบริษัทให้แต่ละอันดับ | นักศึกษา | UC-01 | เลือกบริษัทลงอันดับ 1–5 ได้ บริษัทเดียวเลือกได้อันดับเดียว |
| UC-03 | ล้างอันดับ | นักศึกษา | UC-02 | ล้างทีละอันดับ หรือล้างทั้งหมด |
| UC-04 | ยืนยันการเลือก | นักศึกษา | เลือกครบ 5 อันดับ | อันดับถูกบันทึก เห็นข้อความสำเร็จ |
| UC-05 | ดูอันดับที่บันทึกไว้ | นักศึกษา | UC-04 | เปิดหน้าใหม่แล้วอันดับเดิมยังอยู่ |

**กฎของระบบ**

| หัวข้อ | กฎ |
|---|---|
| บริษัทที่แสดง | เฉพาะบริษัทสถานะ `OPEN` · บริษัท `CLOSED` ไม่แสดง |
| การจัดอันดับ | ต้องเลือกครบ 5 อันดับ · ห้ามเลือกบริษัทเดียวกันในหลายอันดับ · ไม่ครบ → แจ้งว่าเลือกแล้วกี่อันดับ และยังไม่บันทึก |
| การบันทึก | บันทึกอันดับลงตาราง `company_rankings` ผูกกับนักศึกษา · บันทึกใหม่แทนชุดเดิมทั้งหมด |
| การแก้อันดับ | ต้องผ่าน U2 ก่อน (ไม่ผ่าน → 403) · ยื่นคำร้อง (U3) แล้วแก้อันดับไม่ได้ (409) |

Acceptance criteria (ใช้อ้างอิงใน T13–T20)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 | นักศึกษาเห็นรายชื่อบริษัทครบทุกบริษัทที่เปิดรับ และค้นหาจากชื่อได้ |
| TC2 | เลือกบริษัทลงอันดับ 1–5 ได้ บริษัทที่เลือกแล้วไม่แสดงในอันดับอื่น และตัวนับแสดงจำนวนที่เลือก |
| TC3 | เลือกครบ 5 อันดับแล้วกดยืนยัน เห็นข้อความ "สำเร็จ บันทึกลำดับเรียบร้อยแล้ว" และอันดับถูกบันทึก |
| TC4 | กดยืนยันตอนเลือกไม่ครบ 5 อันดับ เห็นข้อความแจ้งว่าต้องแก้อะไร และยังไม่บันทึก |
| TC5 | กลับมาที่หน้าอีกครั้ง อันดับที่บันทึกไว้ยังอยู่ |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role`
- U2 ตรวจสอบคุณสมบัติ: ต้องผ่านก่อนจึงบันทึกอันดับได้
- U3 ยื่นคำร้อง: ยื่นคำร้องแล้วแก้อันดับไม่ได้
- U6 ระบบจับคู่ (Matching): นำอันดับไปจับคู่กับโควตาบริษัท

ไม่อยู่ในขอบเขตของ U4
-
- การเพิ่ม / แก้ไขข้อมูลบริษัทโดยเจ้าหน้าที่ (U4 มีแค่เปิด–ปิดรับบริษัท)
- การเลือกตำแหน่งงานของบริษัท และการจับคู่นักศึกษากับบริษัทตามโควตา (U6)
