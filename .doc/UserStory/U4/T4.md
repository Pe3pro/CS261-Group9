U4:T4 : Requirement กำหนดรายละเอียด User Story (ระบบจับคู่บริษัท (จัดอันดับ))
-
User story U4: นักศึกษาที่มีสิทธิ์ไปฝึกสหกิจเลือกบริษัทที่สนใจและจัดอันดับจากรายชื่อที่คณะเปิดรับ

User story
-
- **As a** นศ.มธ. ที่มีสิทธิ์ไปฝึกสหกิจศึกษา
- **I want to** เลือกบริษัทที่ตนสนใจ หรือจับคู่บริษัทที่ต้องการไปฝึกสหกิจศึกษา จากตัวเลือกที่ทางคณะ / สาขามีและสามารถไปได้
- **So that** นักศึกษาได้บริษัทที่ตนเองสนใจ หรือบริษัทอื่น ๆ ที่อยู่ใน List ได้อย่างถูกต้อง

Pain point ของระบบเดิม
-
| ผู้ได้รับผลกระทบ | ปัญหา |
|---|---|
| นักศึกษา | ไม่รู้ว่าบริษัทไหนยังเปิดรับ และแต่ละตำแหน่งเหลือที่ว่างเท่าไร |
| นักศึกษา | ต้องกรอกรายชื่อบริษัทที่เลือกลงกระดาษ เขียนชื่อผิดหรือเลือกซ้ำได้ |
| เจ้าหน้าที่ | ต้องรวบรวมอันดับที่นักศึกษาเลือกจากกระดาษเอง และตรวจเองว่าตำแหน่งยังว่างไหม |

Stakeholder
-
| Stakeholder | ความต้องการต่อ U4 | หน้าเว็บ |
|---|---|---|
| นักศึกษา (STUDENT) | เห็นเฉพาะบริษัทและตำแหน่งที่เปิดรับ เลือกและจัดอันดับได้เอง เห็นอันดับที่บันทึกไว้ | `ranking.html` |
| เจ้าหน้าที่ฝ่ายสหกิจ (STAFF) | ได้อันดับบริษัทของนักศึกษาที่ถูกต้อง ไม่มีบริษัทซ้ำหรือบริษัทที่ปิดรับแล้ว | – |
| U6 ระบบจับคู่ (Matching) | ใช้อันดับที่บันทึกไว้ไปจับคู่กับโควตาของบริษัท | – |

นักศึกษาต้อง login (U1) และผ่านการตรวจสอบคุณสมบัติ (U2) ก่อน

ขั้นตอนการทำงาน
-
1. นักศึกษาที่ผ่านเกณฑ์เปิดหน้าจับคู่บริษัท ระบบดึงรายชื่อบริษัทที่เปิดรับ (`GET /api/companies`)
2. เลือกบริษัทเพื่อดูตำแหน่งที่เปิดรับและจำนวนที่ว่าง (`GET /api/companies/{id}/positions`)
3. ระบบสร้าง / ใช้ใบสมัครของนักศึกษา (`POST /api/applications`)
4. นักศึกษาเลือกบริษัทและเรียงอันดับ แล้วกด "ยืนยันการเลือก"
5. ระบบตรวจอันดับ แล้วบันทึก (`PUT /api/applications/{id}/choices`) แสดง "สำเร็จ บันทึกลำดับเรียบร้อยแล้ว"
6. กล่อง "ลำดับที่เลือก" แสดงอันดับที่บันทึกแล้ว และยังอยู่เมื่อกลับมาเปิดหน้าอีกครั้ง

Use case
-
| UC | ชื่อ | ผู้ใช้ | เงื่อนไขก่อน | ผลลัพธ์ |
|---|---|---|---|---|
| UC-01 | ดูบริษัทที่เปิดรับ | นักศึกษา | login และผ่าน U2 | เห็นเฉพาะบริษัทสถานะ `OPEN` |
| UC-02 | ดูตำแหน่งของบริษัท | นักศึกษา | UC-01 | เห็นเฉพาะตำแหน่ง `OPEN` ที่ยังมีที่ว่าง เรียงตามชื่อตำแหน่ง |
| UC-03 | จัดอันดับบริษัท | นักศึกษา | UC-02 | กล่องลำดับแสดงบริษัทเรียงตามอันดับที่เลือก |
| UC-04 | ยืนยันการเลือก | นักศึกษา | จัดอันดับถูกต้อง | อันดับถูกบันทึก เห็นข้อความสำเร็จ |
| UC-05 | ดูอันดับที่บันทึกไว้ | นักศึกษา | UC-04 | เปิดหน้าใหม่แล้วอันดับเดิมยังอยู่ |

กฎของระบบ
-
| หัวข้อ | กฎ |
|---|---|
| บริษัทที่แสดง | เฉพาะบริษัทสถานะ `OPEN` · บริษัท `CLOSED` ไม่แสดง |
| ตำแหน่งที่แสดง | เฉพาะตำแหน่งสถานะ `OPEN` และ `availableSlots > 0` · ไม่ปนตำแหน่งของบริษัทอื่น |
| บริษัทที่ไม่มีในระบบ | ได้รายการตำแหน่งว่าง |
| การจัดอันดับ | ต้องเลือกอย่างน้อย 1 บริษัท · ห้ามเลือกบริษัทซ้ำในหลายอันดับ · ผิด → แจ้งว่าต้องแก้อะไร และยังไม่บันทึก |
| การบันทึก | บันทึกอันดับลงตาราง `APPLICATION_CHOICES` ผูกกับใบสมัคร |

Acceptance criteria (ใช้อ้างอิงใน T13–T20)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 | นักศึกษาเห็นรายชื่อบริษัทครบทุกบริษัทที่เปิดรับ และเห็นตำแหน่งที่ยังมีที่ว่าง |
| TC2 | นักศึกษาจัดอันดับแล้วกล่องลำดับแสดงบริษัทเรียงตามอันดับถูกต้อง |
| TC3 | กดยืนยันแล้วเห็นข้อความ "สำเร็จ บันทึกลำดับเรียบร้อยแล้ว" และอันดับถูกบันทึก |
| TC4 | กดยืนยันโดยไม่เลือก หรือเลือกอันดับซ้ำ เห็นข้อความแจ้งว่าต้องแก้อะไร และยังไม่บันทึก |
| TC5 | กลับมาที่หน้าอีกครั้ง อันดับที่เลือกไว้ยังอยู่ |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role`
- U2 ตรวจสอบคุณสมบัติ: ต้องผ่านก่อนจึงเลือกบริษัทได้
- U3 ยื่นคำร้อง: ใบสมัคร (`applications`) ที่อันดับบริษัทผูกอยู่
- U6 ระบบจับคู่ (Matching): นำอันดับไปจับคู่กับโควตาบริษัท

ไม่อยู่ในขอบเขตของ U4
-
- การเพิ่ม / แก้ไขข้อมูลบริษัทและตำแหน่งโดยเจ้าหน้าที่
- การจับคู่นักศึกษากับบริษัทและการตรวจโควตา (U6)
