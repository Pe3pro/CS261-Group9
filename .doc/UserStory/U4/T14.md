U4:T14 : ออกแบบ Integration Test ระหว่าง API กับ DAO (ระบบจับคู่บริษัท (จัดอันดับ))
-
ออกแบบ scenario ทดสอบการเรียกใช้ DAO จาก API ของระบบจับคู่บริษัท (จัดอันดับ)
-


DAO Diagram
-
Controller → Service / Business Logic → DAO / Repository → Entity / ORM → Database


ระบุ scenario API เรียก DAO
-
| ลำดับ | Request | DAO / Repository |
|---|---|---|
| 1 | GET /api/companies | CompanyRepository.findByStatus(OPEN) |
| 2 | GET /api/companies (ไม่มีบริษัทเปิดรับ) | CompanyRepository.findByStatus(OPEN) |
| 3 | GET /api/students/me/company-ranking (ยังไม่เคยบันทึก) | CompanyRankingRepository.findByStudentIdOrderByRankNoAsc(studentId) |
| 4 | PUT /api/students/me/company-ranking (ครบ 5 ไม่ซ้ำ) | CompanyRepository.findAllById · CompanyRankingRepository.deleteByStudentId · saveAll |
| 5 | GET /api/students/me/company-ranking (หลังข้อ 4) | CompanyRankingRepository.findByStudentIdOrderByRankNoAsc(studentId) |
| 6 | PUT /api/students/me/company-ranking (บันทึกชุดใหม่ทับ) | CompanyRankingRepository.deleteByStudentId · saveAll |
| 7 | PUT /api/students/me/company-ranking (มีบริษัท CLOSED) | CompanyRepository.findAllById |
| 8 | PUT /api/students/me/company-ranking (ยื่นคำร้องแล้ว) | ApplicationRepository (ตรวจใบสมัคร) |


เขียน input / expected result
-
| ลำดับ | Input | ผลที่คาดหวัง |
|---|---|---|
| 1 | มีบริษัททั้ง OPEN และ CLOSED | ได้เฉพาะบริษัท OPEN |
| 2 | มีแต่บริษัท CLOSED | ได้ list ว่าง |
| 3 | นักศึกษาที่ยังไม่เคยจัดอันดับ | ได้ list ว่าง |
| 4 | `{"companyIds": [5 ตัว]}` | 200 · ตาราง `company_rankings` มี 5 แถวของนักศึกษา `rank_no` 1–5 |
| 5 | นักศึกษาคนเดิม | ได้อันดับ 1–5 ตรงกับข้อ 4 |
| 6 | `companyIds` ชุดใหม่ 5 ตัว | ชุดเดิมถูกแทนที่ทั้งหมด ยังมี 5 แถว |
| 7 | `companyIds` ที่มีบริษัท CLOSED | 400 `COMPANY_CLOSED` บอกชื่อบริษัท · ตาราง `company_rankings` ไม่เปลี่ยน |
| 8 | ผู้ใช้ที่มีใบสมัคร `SUBMITTED` + `companyIds` 5 ตัว | 409 `RANKING_LOCKED` · ไม่บันทึก |
