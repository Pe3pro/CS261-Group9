U4:T14 : ออกแบบ Integration Test ระหว่าง API กับ DAO (ระบบจับคู่บริษัท (จัดอันดับ))
-
ออกแบบ scenario ทดสอบการเรียกใช้ DAO จาก API ของระบบจับคู่บริษัท (จัดอันดับ)
-


DAO Diagram
-
Controller → Service / Business Logic → DAO / Repository → Entity / ORM → Database


ระบุ scenario API เรียก DAO
-
| ลำดับ | Request | DAO / Repository |
|---|---|---|
| 1 | GET /api/companies | CompanyRepository.findByStatus(OPEN) |
| 2 | GET /api/companies (ไม่มีบริษัทเปิดรับ) | CompanyRepository.findByStatus(OPEN) |
| 3 | GET /api/companies/{id}/positions | CompanyPositionRepository.findOpenPositions(companyId) |
| 4 | GET /api/companies/{id}/positions (มีตำแหน่งที่ปิดแล้ว) | CompanyPositionRepository.findOpenPositions(companyId) |
| 5 | GET /api/companies/{id}/positions (มีหลายบริษัท) | CompanyPositionRepository.findOpenPositions(companyId) |
| 6 | GET /api/companies/{id}/positions (id ไม่มีอยู่) | CompanyPositionRepository.findOpenPositions(companyId) |
| 7 | PUT /api/applications/{id}/choices | ApplicationChoiceRepository |


เขียน input / expected result
-
| ลำดับ | Input | ผลที่คาดหวัง |
|---|---|---|
| 1 | มีบริษัททั้ง OPEN และ CLOSED | ได้เฉพาะบริษัท OPEN |
| 2 | มีแต่บริษัท CLOSED | ได้ list ว่าง |
| 3 | companyId ที่มีตำแหน่งเปิดรับ | ได้เฉพาะตำแหน่ง OPEN ที่ availableSlots > 0 เรียงตาม positionName |
| 4 | companyId ที่มีตำแหน่งถูกปิด | ตำแหน่งที่ปิดไม่แสดง |
| 5 | companyId ของบริษัทหนึ่ง | ไม่ปนตำแหน่งของบริษัทอื่น |
| 6 | companyId ที่ไม่มีในระบบ | ได้ list ว่าง |
| 7 | applicationId + อันดับที่เลือก | บันทึกลง APPLICATION_CHOICES สำเร็จ |
