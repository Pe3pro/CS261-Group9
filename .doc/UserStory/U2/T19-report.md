# U2:T19 System Test Report

## 1. วัตถุประสงค์

ทดสอบการทำงานของระบบตรวจสอบคุณสมบัติตาม Sequence Diagram และ Test Cases ที่ออกแบบไว้ใน `T15-system-test-cases.md`

การทดสอบครอบคลุมการทำงานตั้งแต่หน้า UI ส่งข้อมูลไปยัง REST API ประมวลผลผ่าน Service บันทึกผลผ่าน DAO ลงฐานข้อมูล MySQL และส่งผลกลับมาแสดงบน UI

## 2. ส่วนประกอบที่ทดสอบ

- UI: หน้า `frontend/check.html`
- API: `POST /api/eligibility/check`
- Controller: `EligibilityController`
- Service: `EligibilityService`
- DAO: `EligibilityRecordDao`
- Database: MySQL ตาราง `eligibility_records`

## 3. เครื่องมือที่ใช้

- Java 21
- Spring Boot 4.1.1
- Spring Data JPA
- MySQL 8.4
- Docker
- JavaScript
- Vite
- Chrome DevTools
- PowerShell
- curl

## 4. สภาพแวดล้อมทดสอบ

- Frontend: `http://127.0.0.1:5500`
- Backend: `http://localhost:8080`
- API Endpoint: `POST /api/eligibility/check`
- MySQL Container: `cs261-db`
- Database: `cs261db`

## 6. รายละเอียดผลการทดสอบ

### SYS-SEQ-01: ข้อมูลถูกต้องและผ่านคุณสมบัติ

กรอกข้อมูลนักศึกษาครบถ้วน กำหนด GPA ผ่านเกณฑ์ เกรดและสถานะรายวิชาถูกต้อง และยืนยันเงื่อนไขครบทั้ง 3 ข้อ

ผลที่พบ:

- UI แสดงข้อความผ่านคุณสมบัติ
- API ตอบกลับสำเร็จ
- DAO บันทึกผล `eligible = true`
- ข้อมูลถูกบันทึกลง MySQL

### SYS-SEQ-02: ข้อมูลถูกต้องแต่ไม่ผ่านคุณสมบัติ

กำหนด GPA เป็น `2.74` โดยข้อมูลส่วนอื่นถูกต้องและครบถ้วน

ผลที่พบ:

- UI แสดงข้อความไม่ผ่านคุณสมบัติ
- แสดงเหตุผลว่า GPA ต้องไม่ต่ำกว่า 2.75
- API ตอบ HTTP 200 เนื่องจากรูปแบบข้อมูลถูกต้อง
- DAO บันทึกผล `eligible = false`

## 7. บันทึกระหว่างการทดสอบ

ระหว่าง SYS-SEQ-01 มีการกดส่งข้อมูลด้วยตนเองมากกว่าหนึ่งครั้ง จึงพบข้อมูลหลายรายการในฐานข้อมูล โดยแต่ละรายการมีเวลาบันทึกต่างกันและเกิดจากคนละ Request ไม่ใช่การบันทึกซ้ำภายใน Request เดียว

การเปิด Endpoint ผ่าน Address Bar ของเบราว์เซอร์ได้รับ HTTP 405 เนื่องจากเบราว์เซอร์ส่ง GET แต่ Endpoint รองรับเฉพาะ POST จึงไม่ถือเป็นข้อผิดพลาดของระบบ

ข้อความเตือนของ MySQL เรื่องการใส่รหัสผ่านผ่าน Command Line เป็นคำเตือนด้านความปลอดภัยและไม่ส่งผลต่อผลการทดสอบ
