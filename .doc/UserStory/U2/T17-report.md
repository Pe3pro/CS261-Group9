# U2:T17 รายงานผลการทดสอบ UI กับ API

## 1. วัตถุประสงค์

ตรวจสอบการส่งข้อมูลจากหน้าตรวจสอบคุณสมบัติไปยัง API
และการนำผลตอบกลับมาแสดงบน UI โดยอ้างอิงกรณีทดสอบใน U2:T13

## 2. ขอบเขตและวิธีทดสอบ

แบ่งการทดสอบเป็น 2 ส่วน:

1. ทดสอบอัตโนมัติด้วย Vitest และ JSDOM โดยจำลอง API ผ่าน fetch mock
2. ทดสอบผ่านเบราว์เซอร์กับ Backend จริง และตรวจสอบคำขอผ่าน Network

ผลจาก API จำลองใช้ยืนยันพฤติกรรมของ UI และการสร้างคำขอ
ไม่ได้ยืนยันการประมวลผลของ Backend หรือการบันทึกฐานข้อมูลจริง

## 3. เครื่องมือที่ใช้

- Vitest
- JSDOM
- JavaScript
- Vite
- Spring Boot
- Chrome DevTools
- PowerShell

## 5. ผลการทดสอบกับ API จริง

ทดสอบกรณีกรอกข้อมูลผ่านเกณฑ์บนหน้าเว็บ
แล้วกดตรวจสอบคุณสมบัติ โดยเปิด Chrome DevTools แท็บ Network

| รายการ | ผลที่ตรวจพบ |
|---|---|
| Endpoint | http://localhost:8080/api/eligibility/check |
| Method | POST |
| HTTP Status | 200 OK |
| valid | true |
| eligible | true |
| message | ผ่านคุณสมบัติ |
| errors | รายการว่าง |
| reasons | รายการว่าง |
| warnings | ต้องสอบได้วิชา คพ.302 ก่อนออกปฏิบัติงาน |
| ผลบน UI | แสดงผ่านคุณสมบัติและคำเตือนตรงกับ API |

ผล: ผ่านสำหรับกรณีที่ตรวจสอบนี้

กรณีอื่นในตารางทดสอบอัตโนมัติยังไม่ได้ยืนยันกับ API จริง
ในการทดสอบรอบนี้

## 6. ข้อผิดพลาดและข้อจำกัด

- ไม่พบการทดสอบล้มเหลวในการรันอัตโนมัติทั้ง 9 กรณี
- ไม่พบความคลาดเคลื่อนระหว่าง UI และ API ในกรณีผ่านที่ตรวจสอบจริง
- HTTP 400 และ network error ทดสอบด้วย API จำลอง
- รายงานนี้ไม่ได้ยืนยันผลการบันทึกข้อมูลลงฐานข้อมูล
- ผลผ่านนี้ไม่ได้หมายความว่าระบบไม่มีข้อผิดพลาดในกรณีอื่น

## 8. สรุปผล

การทดสอบอัตโนมัติโดยจำลอง API ผ่านทั้งหมด 9 กรณี
และการทดสอบกรณีผ่านกับ Backend จริงแสดงว่า UI ส่งคำขอ POST
ได้รับ HTTP 200 และแสดงผลตรงกับ JSON Response

ผลการทดสอบกับ API จริงครอบคลุมเฉพาะกรณีผ่านที่มีหลักฐานแนบ
ไม่ถือว่าทุกกรณีได้ทดสอบกับ Backend จริงแล้ว
