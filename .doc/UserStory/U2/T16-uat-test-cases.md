# U2:T16 Design User Acceptance Test

## 1. User Story

**รหัส User Story:** U2

**ชื่อ:** ตรวจสอบคุณสมบัติอัตโนมัติ

**รายละเอียด User Story:**

ในฐานะนักศึกษา ฉันต้องการกรอกข้อมูลการศึกษาและตรวจสอบคุณสมบัติแบบอัตโนมัติ เพื่อให้ทราบว่าตนเองผ่านเกณฑ์สมัครสหกิจศึกษาหรือไม่ พร้อมทราบเหตุผลเมื่อไม่ผ่านและคำเตือนที่เกี่ยวข้อง

## 2. วัตถุประสงค์

ออกแบบ User Acceptance Test เพื่อยืนยันว่าระบบสามารถทำงานได้ตรงตามความต้องการของนักศึกษา และกำหนดเกณฑ์ที่ผู้ใช้งานสามารถยอมรับระบบได้

## 3. Acceptance Criteria

| รหัส | เกณฑ์การยอมรับ |
|---|---|
| AC-01 | นักศึกษาสามารถกรอกข้อมูลที่จำเป็นสำหรับตรวจสอบคุณสมบัติได้ |
| AC-02 | ระบบต้องตรวจว่าข้อมูลถูกกรอกครบถ้วน |
| AC-03 | ระบบต้องตรวจรูปแบบรหัสนักศึกษาและ GPA |
| AC-04 | ระบบต้องตรวจว่า GPA ไม่ต่ำกว่า 2.75 |
| AC-05 | ระบบต้องตรวจว่าเกรดวิชาบังคับเป็น C+ ขึ้นไป |
| AC-06 | ระบบต้องตรวจสถานะรายวิชาตามหลักสูตร |
| AC-07 | ระบบต้องตรวจว่าผู้ใช้ยืนยันเงื่อนไขครบทั้ง 3 ข้อ |
| AC-08 | ระบบต้องแสดงผลผ่านหรือไม่ผ่านคุณสมบัติ |
| AC-09 | ระบบต้องแสดงเหตุผลเมื่อไม่ผ่านคุณสมบัติ |
| AC-10 | ระบบต้องแสดงคำเตือนรายวิชาตามหลักสูตร |
| AC-11 | ข้อมูลไม่ครบหรือผิดรูปแบบต้องไม่ถูกประเมินว่าเป็นผู้ผ่านคุณสมบัติ |

## 5. เกณฑ์การยอมรับ User Story U2

ผู้ใช้งานยอมรับ User Story U2 เมื่อ:

1. นักศึกษากรอกข้อมูลและสั่งตรวจสอบคุณสมบัติได้
2. ระบบแสดงผลผ่านหรือไม่ผ่านอย่างชัดเจน
3. เมื่อไม่ผ่าน ระบบแสดงเหตุผลที่ตรงกับข้อมูล
4. ระบบตรวจพบข้อมูลไม่ครบและข้อมูลผิดรูปแบบ
5. ระบบตรวจ GPA เกรดวิชาบังคับ สถานะรายวิชา และการยืนยันได้
6. ระบบแสดงคำเตือนตามหลักสูตร 61 หรือ 66 ได้
7. ระบบไม่แสดงว่าผ่านเมื่อข้อมูลไม่ถูกต้อง

## 6. สรุป

ออกแบบ User Acceptance Test สำหรับ User Story U2 จำนวน 8 กรณี ครอบคลุมการผ่านคุณสมบัติของหลักสูตร 61 และ 66 การไม่ผ่านเกณฑ์ GPA เกรดและสถานะรายวิชา การยืนยันไม่ครบ การกรอกข้อมูลไม่ครบ และการกรอกข้อมูลผิดรูปแบบ
