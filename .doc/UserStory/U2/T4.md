U2:T4 : Requirement กำหนดรายละเอียด User Story
-
User story U2: ระบบตรวจสอบคุณสมบัติอัตโนมัติ

User story
-
- **As a** นศ.มธ. ที่มี Username Password ของสำนักทะเบียน
- **I want to** ตรวจสอบคุณสมบัติของตนเองได้โดยการกรอกข้อมูลที่กำหนดตามเกณฑ์
- **So that** ทราบผลการตรวจสอบก่อนยื่นคำร้องขอฝึกสหกิจได้อย่างถูกต้องและชัดเจน ทั้งในกรณีที่ผ่านและไม่ผ่าน พร้อมเหตุผลเมื่อไม่ผ่าน

Pain point ของระบบเดิม
-
| ผู้ได้รับผลกระทบ | ปัญหา |
|---|---|
| นักศึกษา | ต้องอ่านเกณฑ์ของหลักสูตรเองและตีความเอง ไม่แน่ใจว่าตัวเองผ่านหรือไม่ |
| นักศึกษา | รู้ว่าไม่ผ่านก็ต่อเมื่อยื่นเอกสารไปแล้ว และไม่รู้ว่าไม่ผ่านเพราะข้อไหน |
| นักศึกษา | ไม่รู้ว่าหลักสูตร 61 และ 66 มีวิชาบังคับและเงื่อนไขต่างกัน |
| เจ้าหน้าที่ | ได้คำร้องจากนักศึกษาที่ยังไม่ผ่านเกณฑ์ ต้องเสียเวลาตรวจและแจ้งกลับทีละคน |

Stakeholder
-
| Stakeholder | ความต้องการต่อ U2 | หน้าเว็บ |
|---|---|---|
| นักศึกษา (STUDENT) | กรอกข้อมูลแล้วรู้ผลทันที ถ้าไม่ผ่านต้องรู้เหตุผลทุกข้อ | `check.html` |
| เจ้าหน้าที่ฝ่ายสหกิจ (STAFF) | ได้รับคำร้องเฉพาะจากนักศึกษาที่ผ่านเกณฑ์ (ต่อใน U3 / U5) | – |
| U3 ยื่นคำร้อง | ใช้ผลการตรวจสอบเป็นเงื่อนไขก่อนเข้าหน้ายื่นคำร้อง | `submit.html` |

นักศึกษาต้อง login (U1) ก่อนจึงเข้าหน้าตรวจสอบคุณสมบัติได้

ขั้นตอนการทำงาน
-
1. นักศึกษา login (U1) แล้วระบบพาไปหน้า `check.html`
2. กรอกรหัสนักศึกษา เลือกหลักสูตร (61 หรือ 66) และกรอก GPAX
3. กรอกเกรดของวิชาบังคับตามหลักสูตร และเลือกสถานะรายวิชา (ยังไม่เคยลง / กำลังศึกษา / เคยศึกษาแล้ว)
4. ยืนยันเงื่อนไขทั้ง 3 ข้อ แล้วกดตรวจสอบคุณสมบัติ
5. หน้าเว็บตรวจความครบถ้วนและรูปแบบก่อน แล้วส่ง `POST /api/eligibility/check`
6. Backend ประเมินตามเกณฑ์ บันทึกผลลงตาราง `eligibility_records` แล้วส่งผล (ผ่าน / ไม่ผ่าน, เหตุผล, คำเตือน) กลับ
7. ผ่าน → แสดงผลผ่านพร้อมคำเตือนของหลักสูตร และปุ่มไปยื่นคำร้อง (U3) · ไม่ผ่าน → แสดงเหตุผลทุกข้อ

Use case
-
| UC | ชื่อ | ผู้ใช้ | เงื่อนไขก่อน | ผลลัพธ์ |
|---|---|---|---|---|
| UC-01 | กรอกข้อมูลการศึกษา | นักศึกษา | login แล้ว | กรอกข้อมูลครบตามหลักสูตรที่เลือก |
| UC-02 | ตรวจสอบคุณสมบัติ | นักศึกษา | UC-01 กรอกครบ | ได้ผลผ่าน / ไม่ผ่าน และผลถูกบันทึก |
| UC-03 | ดูเหตุผลเมื่อไม่ผ่าน | นักศึกษา | ผลไม่ผ่าน | เห็นเหตุผลทุกข้อที่ไม่ผ่าน |
| UC-04 | ไปยื่นคำร้อง | นักศึกษา | ผลผ่าน | ไปหน้ายื่นคำร้อง (U3) ได้ |

เกณฑ์คุณสมบัติ (กฎของระบบ)
-
| หัวข้อ | กฎ |
|---|---|
| หลักสูตร | ต้องเป็น 61 หรือ 66 |
| GPAX | ต้องไม่ต่ำกว่า 2.75 |
| วิชาบังคับ หลักสูตร 61 | คพ.101, คพ.102, คพ.111, คพ.251, คพ.264 |
| วิชาบังคับ หลักสูตร 66 | คพ.100, คพ.101, คพ.102, คพ.111, คพ.251, คพ.261 |
| วิชาบังคับเลือก (ทั้ง 2 หลักสูตร) | ต้องส่งผลการเรียน คพ.213 หรือ คพ.216 อย่างน้อย 1 วิชา |
| เกรดวิชาบังคับ | ต้องได้ C+ ขึ้นไป · เกรดที่รับ: A, B+, B, C+, C, D+, D, F, "ยังไม่เคยเรียน" |
| สถานะรายวิชา หลักสูตร 61 | ต้องส่งสถานะ คพ.384 และวิชาเลือกอย่างน้อย 1 วิชาจาก คพ.266, คพ.322, คพ.348 |
| สถานะรายวิชา หลักสูตร 66 | ต้องส่งสถานะ คพ.180 และวิชาเลือกอย่างน้อย 1 วิชาจาก คพ.262, คพ.331, คพ.240 |
| ค่าสถานะรายวิชา | ต้อง "กำลังศึกษา" หรือ "เคยศึกษาแล้ว" · "ยังไม่เคยลง" ถือว่าไม่ผ่าน |
| รหัสนักศึกษา / GPAX | รหัสนักศึกษาเป็นตัวเลข 10 หลัก · GPAX 0.00–4.00 ทศนิยมไม่เกิน 2 ตำแหน่ง |
| การบันทึกผล | บันทึกลงตาราง `eligibility_records` ทั้งกรณีผ่านและไม่ผ่าน · ข้อมูลผิดรูปแบบไม่บันทึก |
| การยืนยันเงื่อนไข | ต้องยืนยันครบทั้ง 3 ข้อ |
| คำเตือน | หลักสูตร 61: ต้องสอบได้วิชา คพ.302 ก่อนออกปฏิบัติงาน · หลักสูตร 66: ต้องสอบได้วิชา คพ.301 ก่อนออกปฏิบัติงาน |
| ข้อมูลไม่ครบ / ผิดรูปแบบ | รหัสนักศึกษาหรือ GPAX ผิดรูปแบบ หรือกรอกไม่ครบ → ไม่ประเมินว่าผ่าน และแจ้งให้แก้ |
| ผลลัพธ์ | ผ่านเมื่อไม่มีเหตุผลที่ไม่ผ่านเลย · ไม่ผ่านต้องแสดงเหตุผลครบทุกข้อ |

Acceptance criteria
-
| รหัส | เกณฑ์การยอมรับ |
|---|---|
| AC-01 | นักศึกษาสามารถกรอกข้อมูลที่จำเป็นสำหรับตรวจสอบคุณสมบัติได้ |
| AC-02 | ระบบต้องตรวจว่าข้อมูลถูกกรอกครบถ้วน |
| AC-03 | ระบบต้องตรวจรูปแบบรหัสนักศึกษาและ GPA |
| AC-04 | ระบบต้องตรวจว่า GPA ไม่ต่ำกว่า 2.75 |
| AC-05 | ระบบต้องตรวจว่าเกรดวิชาบังคับเป็น C+ ขึ้นไป |
| AC-06 | ระบบต้องตรวจสถานะรายวิชาตามหลักสูตร |
| AC-07 | ระบบต้องตรวจว่าผู้ใช้ยืนยันเงื่อนไขครบทั้ง 3 ข้อ |
| AC-08 | ระบบต้องแสดงผลผ่านหรือไม่ผ่านคุณสมบัติ |
| AC-09 | ระบบต้องแสดงเหตุผลเมื่อไม่ผ่านคุณสมบัติ |
| AC-10 | ระบบต้องแสดงคำเตือนรายวิชาตามหลักสูตร |
| AC-11 | ข้อมูลไม่ครบหรือผิดรูปแบบต้องไม่ถูกประเมินว่าเป็นผู้ผ่านคุณสมบัติ |
