วิธีทดสอบ
-
- Controller / API: JUnit 5 + MockMvc (@WebMvcTest) จำลอง RequestService และ DocumentService ด้วย Mockito
- Service: JUnit 5 + Mockito จำลอง Repository, ที่เก็บไฟล์ (FileStorage), Email (EmailNotifier) และ Clock
- รัน: cd demo → mvnw.cmd test -Dtest=RequestControllerTest,RequestServiceTest,DocumentServiceTest · ผลดิบอยู่ที่ demo/target/surefire-reports/
- Endpoint: GET /api/forms/published, POST /api/requests, PUT /api/requests/{id}/form, POST /api/requests/{id}/documents, POST /api/requests/{id}/submit, GET /api/requests/{id}, GET /api/requests/me (+ GET /api/students/me สำหรับเติมข้อมูลนักศึกษา, GET /api/documents/{id} สำหรับเปิดไฟล์)
- ผู้เรียก API ระบุด้วย header X-User-Id (แบบเดียวกับ API ของ U5) ไม่ส่ง = 401
- ข้อมูลตั้งต้น: นศ. A (ผ่านเกณฑ์ ไม่มีคำร้อง), นศ. B (มีคำร้อง SUBMITTED), นศ. X (ยังไม่ผ่านเกณฑ์), ฟอร์ม F1 (PUBLISHED ยังไม่หมดเขต), F2 (หมดเขตแล้ว)

สรุปผล
-
- API ทั้งหมด 13 ข้อ · ผ่าน 13 · ไม่ผ่าน 0 (RequestControllerTest 13 tests)
- Service ทั้งหมด 10 ข้อ · ผ่าน 10 · ไม่ผ่าน 0 (RequestServiceTest 9 tests + DocumentServiceTest 3 tests)
- ปัญหาที่พบ / การแก้ไข:
  - ก่อนเริ่ม T8 ยังไม่มี API ของ U3 เลย จึงเขียน RequestController / RequestService / DocumentService ตาม API class diagram และ T8 ก่อนรัน
  - ชื่อสถานะในเอกสาร CORRECTION_REQUIRED ตรงกับ NEED_CORRECTION ใน ApplicationStatus ของระบบ (ใช้ enum เดิมที่ U5 ใช้ร่วม)
  - U3-SVC-03 ไม่ตรวจ "อันดับบริษัท (U4)" ก่อนส่ง เพราะ flow ของหน้าเว็บให้จัดอันดับบริษัทหลังยื่นคำร้อง และ backend ยังไม่มีตารางเก็บอันดับ
  - เส้นทางสถานะที่อนุญาตเขียนไว้ใน ApplicationStatus.canMoveTo() (DRAFT/NEED_CORRECTION → SUBMITTED เท่านั้นจากฝั่งนักศึกษา)
  - กดส่งพร้อมกันกันด้วย @Version ของ Application (ครั้งที่สองได้ 409) ทดสอบใน T18 U3-INT-11
