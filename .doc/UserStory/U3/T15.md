U3:T15 Design System Test ตาม Sequence Diagram
-
User story U3: นักศึกษายื่นคำร้องขอฝึกสหกิจศึกษาแบบออนไลน์

ขอบเขต
-
- อ้างอิง Sequence Diagram ใน T6.md (Student → Frontend → Controller → Service → Repository → PostgreSQL → PDF Storage → Email)
- สภาพแวดล้อม: รันระบบครบทุกส่วนด้วย docker-compose (Frontend, Spring Boot, PostgreSQL) และใช้ Email ทดสอบ (เช่น MailHog) แทน Email จริง
- วิธีตรวจ: ทำตามขั้นบนหน้าเว็บ แล้วตรวจผลทั้งบนหน้าจอ ในฐานข้อมูล ในที่เก็บไฟล์ และใน Email

ST-01 ยื่นคำร้องสำเร็จครบ flow (TC1)
-
| ขั้น | Action | Expected result |
|---|---|---|
| 1 | นักศึกษา A login | POST /api/auth/login ได้ 200 และเข้าหน้าตรวจสอบคุณสมบัติ |
| 2 | ไปหน้ายื่นคำร้อง | รหัส คณะ สาขา และ GPA ถูกเติมอัตโนมัติจากฐานข้อมูล |
| 3 | กรอกข้อมูลครบ แนบ transcript.pdf กดส่งแล้วยืนยัน | POST /api/requests ได้ 201 สถานะ DRAFT แล้ว PUT /api/requests/{id}/form ได้ 200 ในตาราง requests มีแถวใหม่สถานะ DRAFT |
| 4 | ระบบอัปโหลดไฟล์ | POST /api/requests/{id}/documents ได้ 201 ไฟล์อยู่ในที่เก็บ PDF และตาราง documents มีแถวพร้อม storageKey |
| 5 | ระบบยื่นคำร้อง | POST /api/requests/{id}/submit ได้ 200 สถานะเปลี่ยนเป็น SUBMITTED และมี submittedAt |
| 6 | ดูผลบนหน้าจอ | แถบผลสีเขียว แสดงเลขที่คำร้อง |
| 7 | ตรวจ Email ของนักศึกษา A | ได้ Email ยืนยันการรับคำร้อง |
| 8 | เจ้าหน้าที่ S login แล้วเปิดหน้ารายการคำร้อง | เห็นคำร้องของนักศึกษา A ในรายการรอตรวจ และเปิดดูไฟล์ PDF ได้ |

ST-02 ยื่นซ้ำ (TC3)
-
| ขั้น | Action | Expected result |
|---|---|---|
| 1 | นักศึกษา B login แล้วไปหน้ายื่นคำร้อง | แจ้งว่ามีคำร้องอยู่แล้ว แสดงเลขที่และสถานะ ปุ่มส่งกดไม่ได้ |
| 2 | ยิง POST /api/requests/{id}/submit ตรงด้วย Postman (ข้ามหน้าเว็บ) | ได้ 409 Conflict |
| 3 | ตรวจฐานข้อมูล | คำร้องของ B มีแค่แถวเดิม สถานะไม่เปลี่ยน |
| 4 | ตรวจที่เก็บ PDF และ Email | ไม่มีไฟล์ใหม่ และไม่มี Email ใหม่ |

ST-03 ยื่นหลังหมดเขต (TC4)
-
| ขั้น | Action | Expected result |
|---|---|---|
| 1 | ตั้งวันหมดเขตของฟอร์ม F1 เป็นเมื่อวาน | – |
| 2 | นักศึกษา A login แล้วไปหน้ายื่นคำร้อง | แจ้งว่าหมดเขตแล้ว ปุ่มส่งกดไม่ได้ |
| 3 | ยิง POST /api/requests/{id}/submit ตรงด้วย Postman | ได้ 409 Conflict รหัส DEADLINE_PASSED |
| 4 | ปรับนาฬิกาเครื่องนักศึกษาย้อนไปก่อนหมดเขตแล้วลองใหม่ | ยังถูกปฏิเสธ เพราะระบบใช้เวลาของ server |
| 5 | ตรวจฐานข้อมูลและ Email | สถานะไม่เป็น SUBMITTED และไม่มี Email |

ST-04 เจ้าหน้าที่ส่งกลับให้แก้ไข แล้วนักศึกษาส่งใหม่ (TC2)
-
| ขั้น | Action | Expected result |
|---|---|---|
| 1 | เจ้าหน้าที่ S เปิดคำร้องของนักศึกษา A แล้วส่งกลับให้แก้ พร้อมเหตุผล | สถานะเปลี่ยนเป็น CORRECTION_REQUIRED และนักศึกษา A ได้ Email แจ้งให้แก้ไข |
| 2 | นักศึกษา A เปิดหน้ายื่นคำร้อง | เห็นข้อความว่าต้องแก้ไขพร้อมเหตุผล และกรอกได้ |
| 3 | แก้เบอร์โทร อัปโหลด PDF ใหม่ แล้วกดส่งก่อนหมดเขต | ใช้คำร้องเดิม (id เดิม) สถานะกลับเป็น SUBMITTED |
| 4 | เจ้าหน้าที่ S เปิดดูอีกครั้ง | เห็นเบอร์โทรใหม่และไฟล์ PDF ฉบับล่าสุด |
