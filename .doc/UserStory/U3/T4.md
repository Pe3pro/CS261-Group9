U3:T4 : Requirement กำหนดรายละเอียด User Story
-
User story U3: นักศึกษายื่นคำร้องขอฝึกสหกิจศึกษาแบบออนไลน์ แล้วระบบส่งต่อให้เจ้าหน้าที่ได้อย่างถูกต้องครบถ้วน

User story
-
- **As a** นศ.มธ. ที่ต้องการยื่นคำร้องขอฝึกสหกิจศึกษา
- **I want to** ยื่นคำร้องขอฝึกสหกิจศึกษาแบบออนไลน์ กรอกแบบฟอร์ม แนบ Transcript และติดตามสถานะได้เอง
- **So that** สามารถสร้างคำร้องและยื่นได้ในระบบ โดยส่งไปถึงผู้ที่เกี่ยวข้องได้อย่างถูกต้องครบถ้วน

Pain point ของระบบเดิม
-
| ผู้ได้รับผลกระทบ | ปัญหา |
|---|---|
| นักศึกษา | ต้องกรอกแบบฟอร์มกระดาษและเดินไปยื่นที่ฝ่ายสหกิจ · ไม่รู้ว่าเอกสารครบหรือยังจนกว่าเจ้าหน้าที่จะตรวจ · ไม่รู้สถานะคำร้องต้องโทรหรือเดินไปถาม |
| นักศึกษา | ถ้าข้อมูลผิดหรือขาดต้องกรอกใหม่ทั้งฉบับ · ไม่รู้วันหมดเขตที่ชัดเจน |
| เจ้าหน้าที่ | ได้คำร้องที่ข้อมูลไม่ครบหรือเอกสารผิดประเภท ต้องตามนักศึกษาเพิ่ม · คำร้องซ้ำของคนเดียวกัน · ต้องคีย์ข้อมูลจากกระดาษเข้าระบบเอง |
| อาจารย์ที่ปรึกษา | รอคำร้องที่ผ่านเจ้าหน้าที่นาน เพราะเอกสารเดินทางทางกระดาษ |

Stakeholder
-
| Stakeholder | ความต้องการต่อ U3 | หน้าเว็บ |
|---|---|---|
| นักศึกษา (STUDENT) | ยื่นคำร้องเองได้ทุกที่ รู้ทันทีว่าต้องแก้ช่องไหน เห็นเลขที่และสถานะคำร้อง | `submit.html` |
| เจ้าหน้าที่ฝ่ายสหกิจ (STAFF) | ได้คำร้องที่ข้อมูลครบ เอกสารเป็น PDF จริง ไม่มีคำร้องซ้ำ · เปิดแบบฟอร์มและกำหนดวันหมดเขตได้ (U5) | `staff-forms.html`, `staff-review.html` |
| อาจารย์ที่ปรึกษา (ADVISOR) | ได้รับคำร้องที่เจ้าหน้าที่ตรวจแล้วต่อทันที (U5) | `staff-review.html` |
| สำนักทะเบียน (TU REST API) | เป็นแหล่งข้อมูลบัญชีและข้อมูลนักศึกษา (U1) | – |

ทุกคน login ที่ `login.html` (U1) ก่อน · role มาจาก backend ไม่ต้องเลือกเอง · นักศึกษาต้องผ่านการตรวจสอบคุณสมบัติ (U2) ก่อนจึงเข้าหน้ายื่นคำร้องได้

ขั้นตอนการทำงาน
-
1. นักศึกษา login แล้วผ่านการตรวจสอบคุณสมบัติ (U2)
2. เปิดหน้ายื่นคำร้อง ระบบโหลดแบบฟอร์มที่เปิดใช้งานอยู่และวันหมดเขต พร้อมเติมรหัส ชื่อ คณะ สาขา และ GPA จากระบบ (แก้ไขไม่ได้)
3. ระบบตรวจว่ามีคำร้องเดิมไหม: มีคำร้องค้าง → แจ้งเลขที่และสถานะ ไม่ให้ยื่นซ้ำ · ถูกส่งกลับแก้ไข → แสดงเหตุผลและเติมข้อมูลเดิมให้แก้
4. นักศึกษากรอกข้อมูล (ชื่อ เบอร์โทร อีเมล ที่อยู่) และแนบ Transcript เป็น PDF · บันทึกร่างไว้กลับมากรอกต่อได้
5. กดส่ง → ระบบถามยืนยัน → สร้างคำร้อง `DRAFT` → บันทึกคำตอบ → อัปโหลด PDF → ยื่นจริง เปลี่ยนเป็น `SUBMITTED` และบันทึกเวลาส่ง
6. ระบบแสดงผลสำเร็จพร้อมเลขที่คำร้อง ส่ง Email ยืนยันการรับคำร้อง และคำร้องเข้ารายการ "รอตรวจ" ของเจ้าหน้าที่ (U5)
7. ถ้าเจ้าหน้าที่ส่งกลับแก้ไข (`NEED_CORRECTION`) นักศึกษาแก้แล้วส่งใหม่ได้ด้วยคำร้องเลขที่เดิม

| UC-01 | ดูแบบฟอร์มและข้อมูลของตัวเอง | นักศึกษา | login และผ่าน U2 | เห็นแบบฟอร์มที่เปิดใช้งาน วันหมดเขต และข้อมูลนักศึกษาที่เติมไว้ |
| UC-02 | กรอกแบบฟอร์มและบันทึกร่าง | นักศึกษา | UC-01 | ข้อมูลที่กรอกไว้ไม่หายเมื่อปิดแล้วเปิดหน้าใหม่ |
| UC-03 | แนบ Transcript | นักศึกษา | มีคำร้องของตัวเอง | ไฟล์ PDF ถูกเก็บและผูกกับคำร้อง · ไฟล์ผิดประเภทหรือเกินขนาดถูกปฏิเสธ |
| UC-04 | ยื่นคำร้อง | นักศึกษา | กรอกครบ แนบ PDF แล้ว ยังไม่หมดเขต | สถานะ `SUBMITTED` ได้เลขที่คำร้อง และ Email ยืนยัน |
| UC-05 | ดูสถานะคำร้อง | นักศึกษา | ยื่นแล้ว | เห็นเลขที่และสถานะล่าสุด |
| UC-06 | แก้ไขคำร้องที่ถูกส่งกลับแล้วส่งใหม่ | นักศึกษา | คำร้องสถานะ `NEED_CORRECTION` | เห็นเหตุผล แก้แล้วส่งใหม่ได้ เลขที่เดิม สถานะ `SUBMITTED` |
| UC-07 | รับคำร้องเข้าตรวจ | เจ้าหน้าที่ | นักศึกษายื่นสำเร็จ | เห็นคำร้องพร้อมข้อมูลนักศึกษา คำตอบทุกช่อง และเปิด PDF ได้ (ต่อใน U5) |

กฎของระบบ
-
| หัวข้อ | กฎ |
|---|---|
| ผู้ยื่น | ต้อง login เป็นนักศึกษา (ไม่ส่งตัวตน → 401) · เห็นและแก้ได้เฉพาะคำร้องของตัวเอง (ของคนอื่น → 403) |
| แบบฟอร์ม | ยื่นได้เฉพาะแบบฟอร์มที่เปิดใช้งาน (PUBLISHED) · ไม่มีแบบฟอร์มเปิด → แจ้ง "ยังไม่มีแบบฟอร์มที่เปิดให้ยื่น" |
| ข้อมูลที่กรอก | ทุกช่องบังคับต้องกรอก (เว้นวรรคอย่างเดียวถือว่าว่าง) · เบอร์โทรและอีเมลต้องถูกรูปแบบ · ผิด → 400 พร้อมรายชื่อช่องที่ผิด |
| Transcript | ต้องเป็นไฟล์ .pdf และเนื้อไฟล์ต้องเป็น PDF จริง · ขนาดไม่เกิน 10 MB · ผิด → 400 · แนบใหม่แทนไฟล์เดิม |
| ยื่นซ้ำ | มีคำร้องที่ยังไม่จบอยู่แล้ว → 409 ไม่สร้างฉบับใหม่ · คำร้องเดิมที่ถูกปฏิเสธ (`REJECTED`) ยื่นใหม่ได้ |
| หมดเขต | ใช้เวลาของ server เทียบกับวันหมดเขตของแบบฟอร์ม · ส่งตรงเวลาหมดเขตพอดีได้ เลยไป 1 วินาที → 409 `DEADLINE_PASSED` |
| การส่ง | ต้องแนบ PDF ก่อน (ไม่แนบ → 400) · ส่งได้เฉพาะสถานะ `DRAFT` หรือ `NEED_CORRECTION` · กดส่งซ้ำหรือส่งพร้อมกันได้คำร้อง `SUBMITTED` เพียงฉบับเดียว |
| สถานะ | `DRAFT` → `SUBMITTED` → (U5) `UNDER_REVIEW` → `APPROVED` · ส่งกลับเป็น `NEED_CORRECTION` แล้วส่งใหม่เป็น `SUBMITTED` · `APPROVED` และ `REJECTED` แก้ไขต่อไม่ได้ |
| การแจ้งเตือน | ยื่นสำเร็จส่ง Email ยืนยันถึงนักศึกษา |

Acceptance criteria (test case หลักของ U3 ใน Trello)
-
| เคส | เงื่อนไข |
|---|---|
| TC1 ยื่นสำเร็จ | นักศึกษาที่ผ่านเกณฑ์กรอกข้อมูลครบ แนบ PDF แล้วส่งได้ ได้เลขที่คำร้อง สถานะ `SUBMITTED` และเจ้าหน้าที่เห็นคำร้องพร้อมข้อมูลครบ |
| TC2 ข้อมูลตกหล่น/แก้ไขได้ | ข้อมูลไม่ครบ ผิดรูปแบบ หรือไม่แนบ PDF ส่งไม่ได้ และระบบบอกช่องที่ต้องแก้ · ข้อมูลที่กรอกไว้ไม่หาย · คำร้องที่ถูกส่งกลับแก้แล้วส่งใหม่ได้ด้วยเลขที่เดิม |
| TC3 ยื่นซ้ำ | นักศึกษาที่มีคำร้องอยู่ระหว่างดำเนินการยื่นอีกไม่ได้ ระบบแจ้งเลขที่และสถานะเดิม และไม่เกิดคำร้องซ้ำ |
| TC4 ยื่นหลังหมดเขต | เลยวันและเวลาหมดเขตแล้วส่งไม่ได้ ระบบแจ้งว่าเกินระยะเวลาที่กำหนด แม้เปลี่ยนนาฬิกาเครื่องก็ส่งไม่ได้ |

ขึ้นกับ User Story อื่น
-
- U1 Login: ให้ `userId` และ `role` (หน้า U3 ส่ง `X-User-Id` ไปกับทุก request)
- U2 ตรวจสอบคุณสมบัติ: ต้องผ่านก่อนจึงเข้าหน้ายื่นคำร้องได้
- U5 เจ้าหน้าที่: สร้างและเปิดใช้งานแบบฟอร์มพร้อมวันหมดเขต · รับคำร้อง `SUBMITTED` ไปตรวจ และส่งกลับแก้ไขพร้อมเหตุผล

ไม่อยู่ในขอบเขตของ U3
-
- การสร้างแบบฟอร์มและการพิจารณาคำร้องของเจ้าหน้าที่/อาจารย์ (U5) · การจับคู่และจัดอันดับบริษัท (U4, U6)
- ส่ง Email ผ่าน mail server จริง (ตอนนี้เขียนลง log ของ backend)
- ยกเลิกหรือถอนคำร้องที่ยื่นไปแล้ว
