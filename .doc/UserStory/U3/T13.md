U3:T13 Design Integration Test ระหว่าง UI กับ API
-
User story U3: นักศึกษายื่นคำร้องขอฝึกสหกิจศึกษาแบบออนไลน์

ขอบเขต
-
- ทดสอบหน้า submit.html เรียก API จริง (backend รันอยู่ ฐานข้อมูลเป็นฐานข้อมูลทดสอบ)
- API ที่เกี่ยวข้อง (ตาม T5.md): GET /api/applications, POST /api/applications, POST /api/documents, POST /api/applications/{id}/submit
- วิธีตรวจ: เปิด DevTools แท็บ Network ดู request ที่หน้าเว็บส่ง และดูการแสดงผลบนหน้าจอ

ข้อมูลตั้งต้น
-
| ชื่อ | ค่า |
|---|---|
| นักศึกษา A | studentId 1, รหัส 6609650001, ยังไม่มีคำร้อง |
| นักศึกษา B | studentId 2, รหัส 6609650002, มีคำร้องสถานะ SUBMITTED |
| นักศึกษา C | studentId 3, รหัส 6609650003, มีคำร้องสถานะ NEED_CORRECTION |
| ฟอร์ม F1 | formTemplateId 10, ยังไม่หมดเขต |
| ฟอร์ม F2 | formTemplateId 11, หมดเขตแล้ว |
| ข้อมูลครบ | ชื่อ สมชาย ใจดี, เบอร์โทร 0812345678, อีเมล somchai@dome.tu.ac.th, ที่อยู่ 99 ม.ธ. รังสิต, transcript.pdf |

Test cases
-
| TC ID | Scenario | Input (บนหน้าเว็บ) | Request ที่ต้องเห็น | Response | Expected result บนหน้าเว็บ |
|---|---|---|---|---|---|
| IT-UA-01 | ยื่นสำเร็จ (TC1) | นักศึกษา A ฟอร์ม F1 กรอกข้อมูลครบ แนบไฟล์ แล้วกดส่ง | POST /api/applications (studentId 1, formId 10, คำตอบครบ 4 ช่อง) แล้ว POST /api/documents แล้ว POST /api/applications/{id}/submit | 201, 201, 200 สถานะ SUBMITTED | แถบผลสีเขียว แสดงเลขที่คำร้อง และมีปุ่มไปจับคู่บริษัท |
| IT-UA-02 | เปิดหน้าตอนยังไม่เคยยื่น | นักศึกษา A เปิดหน้ายื่นคำร้อง | GET /api/applications?studentId=1&formId=10 | 200 ค่าว่าง | กรอกและกดส่งได้ตามปกติ |
| IT-UA-03 | ข้อมูลไม่ครบหลุดไปถึง server (TC2) | ปิดการตรวจฝั่งหน้าเว็บ แล้วส่งโดยเบอร์โทรว่าง | POST /api/applications | 400 VALIDATION_ERROR | แสดงข้อความ error จาก server อยู่หน้าเดิม ข้อมูลที่กรอกไม่หาย |
| IT-UA-04 | ไฟล์ไม่ใช่ PDF | แนบไฟล์ photo.exe แล้วกดส่ง | POST /api/documents | 400 | แสดงข้อความ Transcript ต้องเป็นไฟล์ PDF |
| IT-UA-05 | **ยื่นซ้ำ (TC3)** | นักศึกษา B กรอกข้อมูลครบแล้วกดส่ง | POST /api/applications/{id}/submit | 409 DUPLICATE_APPLICATION | แถบผลสีแดง ข้อความ "คุณมีคำร้องประเภทนี้ที่อยู่ระหว่างดำเนินการแล้ว" ไม่มีปุ่มไปจับคู่บริษัท |
| IT-UA-06 | **เปิดหน้าตอนมีคำร้องค้าง (TC3)** | นักศึกษา B เปิดหน้ายื่นคำร้อง | GET /api/applications?studentId=2&formId=10 | 200 สถานะ SUBMITTED | แจ้งว่ายื่นคำร้องแล้ว แสดงเลขที่และสถานะ ปุ่มส่งกดไม่ได้ |
| IT-UA-07 | **ยื่นหลังหมดเขต (TC4)** | นักศึกษา A ฟอร์ม F2 กรอกข้อมูลครบแล้วกดส่ง | POST /api/applications/{id}/submit | 422 DEADLINE_PASSED | แถบผลสีแดง ข้อความ "เกินระยะเวลาที่กำหนด ไม่สามารถยื่นคำร้องได้" ไม่มีปุ่มแก้ไขและปุ่มไปจับคู่บริษัท |
| IT-UA-08 | แก้ไขคำร้องที่ถูกส่งกลับ (TC2) | นักศึกษา C แก้เบอร์โทรแล้วกดส่ง | POST /api/applications (ได้ id เดิม) แล้ว POST /api/applications/{id}/submit | 200 สถานะ SUBMITTED | แถบผลสีเขียว เลขที่คำร้องเป็นเลขเดิม |
| IT-UA-09 | ไม่พบคำร้อง | เรียก submit ด้วย id ที่ไม่มี | POST /api/applications/999999/submit | 404 NOT_FOUND | แสดงข้อความไม่พบคำร้อง |
| IT-UA-10 | server ไม่ทำงาน | ปิด backend แล้วกดส่ง | ไม่มี response (network error) | – | แสดงข้อความ "ไม่สามารถเชื่อมต่อระบบได้" และมีปุ่มลองใหม่ |
